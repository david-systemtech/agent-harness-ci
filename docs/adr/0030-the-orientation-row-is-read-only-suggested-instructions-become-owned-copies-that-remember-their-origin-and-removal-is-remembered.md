# The Orientation row is read-only and previewed as rendered, suggested instructions become owned copies that remember their origin, scope is per account and on for all, and removal is remembered

Decided 2026-09-25 on the map ticket "Generated Setup prompts: rendering rules, on by default, edit and remove semantics" (david/agent-harness issue 44), which ADR 0016 re-scoped once the three generated Setup prompts became the orientation block of ADR 0011: this ticket is the editable prose around the block and the suggested instruction copies in the user layer (ADR 0009). Today's Instructions pane is a list with one editor open, scopes each prompt to accounts and greys out an account whose adapter takes no appended prompt, deletes a built-in by turning it off because the read path re-appends any built-in the document lacks, and lets exactly one built-in be taken over; the suggestions catalogue prototype carries instruction groups (a generated Setup group, Coding, Working with me, Custom) with an id, version and text per entry. **The Instructions list opens with a read-only Orientation row**: rendered from the registry now and previewed as rendered, its verification lines included, never edited and never removed, with an off switch that warns the model will then not know where its forge, keys and banks are. **Beside it the step seeds one ordinary owned instruction**, "About my setup", from the catalogue's Setup text, which the user edits, switches off or removes like any other; the facts stay in the block and the prose is the user's. **Ticking a suggestion creates an owned copy that remembers its origin**, the catalogue id and version it came from; when the catalogue ships a newer version the row shows a badge with See what changed (the diff), Replace with the new text (the user's edits are lost, and the action says so) or Keep mine (the badge clears until the next version); nothing updates silently, an unedited copy included. **Scope is per account and on for every account by default**: each instruction row shows the environment's accounts as chips, a new or ticked instruction reaching all of them, since an instruction is a habit and costs little where an always-on skill costs tokens (ADR 0029); an account whose adapter has no instruction channel (Codex until milestone 2) shows dim with the reason, never hidden; Same on every environment copies the instruction and its scope by account identity. **Removal is remembered**: removing a copy marks the catalogue entry dismissed on this environment, the catalogue showing it under a collapsed Dismissed fold with Restore; turning an instruction off keeps the copy; the seeded note follows the same rule.

## Considered options

- Prose fields inside the Orientation row, or the block with no seeded prose: rejected; prose that cannot be scoped or removed on its own, or every user writing the same note from scratch.
- Unedited copies updating themselves, or copies that forget their origin: rejected; text the model reads would change unseen, or there would be no update path at all.
- On for the default account only, or environment-wide with no per-account scope: rejected; an instruction is cheap enough to reach every account, and the Codex gap needs somewhere to be shown.
- Removal not remembered, or off-only with no removal: rejected; a rejected suggestion would keep returning, or the list would fill with switched-off rows.

## Consequences

- The skills-and-instructions spec (issue 89) carries the owned-instruction record (title, body, origin id and version, scope by account, enabled), the dismissed set, the Orientation row's preview and off switch, and the diff view; the Set up spec (issue 88) holds the Instructions step: the Orientation preview, the seeded note, the group tick lists and Custom.
- Chosen defaults for review: the team-bank layer's entity-routing and duplicate-to-personal lines stay in the rendered bank layer (ADR 0010), never in an owned copy; the step is done once the Orientation block renders and needs attention when a registry read fails, naming the registry, and is never skipped; Custom is a free editor with a title and a Markdown body; the catalogue's Setup group holds only the seed text; the four layers compose in the order user, team bank, project, session (ADR 0009); the bulk edit's dismissed set is copied only when the user ticks it.
- Fog: a per-bot persona editor when the Bot object lands (ADR 0008); the planning-mode strip that could suggest an instruction beside a skill.
