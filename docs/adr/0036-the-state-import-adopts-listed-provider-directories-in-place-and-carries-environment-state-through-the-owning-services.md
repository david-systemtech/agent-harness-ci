# The state import adopts listed provider directories in place and carries environment state through the owning services

Decided 2026-09-28 on the map ticket for the state import (david/agent-harness issue 56), re-scoped by ADR 0021 to what lives outside the adopted Claude Code directory. The source keeps its state as plain JSON in a data folder per machine (an application-data folder on a desktop, a data directory on a server), holding `profiles.json` (one provider login per config directory), `prefs.json` (archive, pins, groups and window preferences, desktop only), `memory-banks.json`, `skills.json`, `agent-prompts.json`, `routines.json` and `serverRoutines.json`, `serverSessions.json` (which connection ran which session, and whether a program did), `secret-managers.json`, `memory-bank-tokens.json` and `paired-browsers.json`; its terminal client keeps `preferences.json` (pins, drafts, after-edit commands), `history.jsonl` and `snippets.json` in a separate state folder. On a desktop, the source encrypts bank tokens, key-manager credentials and local-model keys with its own keychain entry, which no other program can decrypt. On SAMPLE-SERVER there is no signed-in `~/.claude`: every Claude session lives in a profile directory under `/data/profiles/`, so Carry over as ADR 0021 left it would bring none of them. The **state import** is an environment command at `admin`, with a dry run, that reads the source data folder and its terminal client's state folder on its own machine and writes through the services that own each kind of state (accounts, session state, skills, instructions, banks, forges, key managers, routines, the browser's page policy), appending with origin `import`. The Carry over card shows a section for it only when a source folder is detected, and the CLI has a verb for headless environments; it re-runs like Carry over, offering only what is new, deduplicated by source ids.

- **Accounts, amending ADR 0018**: every Claude config directory listed in `profiles.json` is adopted in place on the same terms as the machine's own directory (written only by the provider's CLI and read by the harness only to import, never moved, linked or deleted), and Carry over then runs for each adopted account. Directories not listed are ignored. When two listed directories are signed in as one identity, the most recently used is adopted and the other is read only as an import source: its sessions import under that account, their history read from where they sit on first open, and its credentials are never used. The source's active profile becomes the environment's default account; labels carry, made unique.
- **Other providers**: local-model, Codex and OpenCode profiles are named on the report as arriving with their milestone-2 adapters, and a re-run then carries them with their sessions and archive state. Saved server connections are never carried; the report points at Your machines.
- **Organisation state**: a session is archived when its provider tag says so or a leftover archive key in `prefs.json` names it (the only record for providers without a tag). Pins are the union of the source desktop's `profileId:sessionId` keys and its terminal client's bare ids; groups carry by name in their order, merged into same-named environment groups (ADR 0003). A key naming a session this environment does not hold is counted on the report and dropped. Sessions a program started (ledger origin `program` or `bridge`, or an ephemeral connection workspace) and every session a routine fired import archived, as ADR 0021 archives scheduler-spawned ones.
- **Forges and secrets**: per-bank forge credentials become forge accounts by ADR 0020's rule (one per canonical origin, a key-manager reference winning); a reference carries as is, and an account whose only credential is an encrypted token is added with credential `none`, named on the report with a link to Forges. Key-manager connections carry as records (address, CA, auth method, username) awaiting sign-in on the Key manager step. Plaintext tokens are never copied.
- **Banks**: each registry entry becomes one on the environment pointing at its existing checkout, with its role as read-write or read-only attach, and its profile scope mapped to the adopted accounts; the source's default bank becomes the environment's default. A bank without `BANK.md` shows needs attention until ADR 0013's migration. The master memory switch and the follow-ups-as-issues flag are dropped.
- **Routines**: every routine imports disabled onto the environment of the machine it came from, except the upstream watch, which the routines specification imports from its document. A connection-pinned workspace becomes a workspace request; history does not carry.
- **Instructions and skills**: custom prompts and overridden built-in ones become owned instructions scoped by the mapped accounts, enabled as they were (ADR 0030); untouched built-ins and the dismissed list are dropped. Tracked repositories become skill sources with their branch or pin, and always-on names apply per mapped account, unknown names reported (ADR 0029).
- **Client-local state**: only values with a settings row carry (theme mode, font size, conversation width, show-thinking, and the last settings address through ADR 0027's map). The command returns them, and the client that ran it applies them only when it runs on the source's machine; otherwise they are listed as not applied. The harness terminal UI has a one-time flag that reads the source terminal client's state folder for prompt history, snippets and after-edit commands. Drafts are session fields and carry on the environment, only into an empty draft. Composer seeds, per-session model choices, dock layouts and file frecency are dropped.
- **Browser**: dev sites and the evaluate-everywhere policy carry into the local environment's page policy; pairings are listed with a pointer to the Browser step (ADR 0024).
- **Naming**: the state import's source reader, `packages/environment/src/state-import/source/`, is the one place allowed to contain the source product's folder names and environment variables, because detection needs them; the name grep AGENTS.md asks for skips that directory's files before a push and nothing else; posts on the tracker get no exemption.

## Considered options

- Copying a profile directory into a harness-owned one: rejected; two copies of one sign-in rotate each other's refresh token out.
- A fresh sign-in with the old directory read only for sessions: rejected; it adds a sign-in per profile for nothing the in-place adoption lacks.
- A folder field with no detection, or an importer kept in another repository: rejected; the first hides the import from the people it is for, the second takes it off the Carry over card.
- Skipping or importing normally the sessions programs and routines started: rejected; skipping loses them, importing normally floods the list.

## Consequences

- The Set up specification (issue 88) gains the state-import section on the Carry over card and its report; the banks (90), key-manager (91), routines (92) and switch-over (94) specifications each implement their part through their own commands.
- Source state changed after an import is not followed; a re-run offers only what is new.
