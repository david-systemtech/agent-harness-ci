# The LLM step mints a tagged session, embeds it, and detects its artefact with the step's health check; agents get no settings write surface

Decided 2026-09-23 on the map ticket "LLM step contract: prompt minting, account and model picker, artefact detection, failure" (david/agent-harness issue 40), which ADR 0016 let stand from the 2026-09-22 wizard map. Artemis's "Describe this bank" opens a conversation column in the bank's checkout, sends a fixed prompt kept in the protocol package, keeps the prompt as an editable draft when the column has no account or model, and then knows nothing more: nothing detects whether `BANK.md` landed. The harness's **LLM step** is any Set up step whose artefact has to be authored rather than filled in: the body of a `BANK.md` (issue 46), a standing instruction tailored from a catalogue entry (issue 44). It issues one command on the environment it is checking that creates a **minted session**: a workspace that fits the artefact (the bank's checkout, or a scratch workspace for an instruction), the account, model family and effort from a picker that preselects the environment's default (ADR 0018) and remembers a change for the rest of this checklist run, a tag naming the step, and the step's prompt sent as the first message, or held as the session's draft when no account or model resolves. The step card embeds the session's transcript and composer from the client runtime under a status line (running, waiting for you, landed) with a link to open it in the main window, so first launch, where Set up is the whole window, and a later re-run from Settings behave alike. **Detection is the step's health check**: it re-runs at every run end of the minted session and on a Check now button, and passes when the artefact is where the prompt said. For a bank, `BANK.md` on the bank's main passing the ADR 0013 validator, or an open pull request holding it on a bank whose merges are reviewed, shown as landed and awaiting review. For an instruction, a file at the path the prompt named in the scratch workspace, which the step imports as an owned instruction in the user layer tagged with its origin and shows for a final edit. Prompts live in the harness's shared protocol package, one per LLM step, rendered from live facts and versioned with the validator they must satisfy. **Agents get no write surface into settings**: the artefact is always a file the harness reads.

## Considered options

- Prefilling the composer and letting the user send, or running the prompt headless with no visible session: rejected; one extra click every time, or a conversation nobody can steer.
- Live watchers on the file, branch and pull request, or a harness tool the agent calls to mark the step done: rejected; a run boundary is a good enough moment, and a tool is the write surface the 2026-09-22 decision refused and a local model cannot be relied on to call.
- A harness tool that writes the instruction, or copying the agent's final message: rejected for the same reason, and because a file is the reviewable artefact.
- A soft timeout to needs attention, or a hard timeout that interrupts: rejected; the run belongs to the environment, unattended runs are governed by ADR 0006's TTLs, and a long authoring session is a feature.
- Discarding a failed session and retrying, or falling back to the shipped template without a model: rejected; the transcript explains the failure and a silent downgrade hides it.
- Prompts in the suggestions catalogue fetched at launch: rejected; they would drift from the validator the harness ships.

## Consequences

- No timeout and no blocking: Skip for now moves the checklist on while the session keeps running, and the step flips to done at the next run end that passes the check or on Check now. A parked question or permission shows on the card as waiting for you and is answerable there.
- An errored or interrupted run leaves the step at needs attention with the error or "stopped" and three actions: Try again resumes the same session with a continue message; Write it myself opens the artefact for manual authoring; Start over mints a fresh session with the same prompt, the old one staying in the list. A check that fails after a clean run end names what is missing. A done step offers Revise, which mints a new session with the revise variant of the prompt and the existing artefact in the workspace.
- A minted session runs under the connection's ceiling with the environment's default mode (ADR 0006), receives the forge token and git credentials of ADR 0012 so it can land through the bank's review path, and is an ordinary session everywhere else. The contract does not depend on a provider feature, so it works with the milestone-2 adapters and local models.
- Running an LLM step needs a client that renders the card; the terminal UI shows the checklist summary and points at one (ADR 0016).
