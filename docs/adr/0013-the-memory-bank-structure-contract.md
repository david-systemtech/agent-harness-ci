# The memory bank structure contract: tiers with write-time caps, a pointer may replace a group, a line is never cut

Decided 2026-09-23 on the map ticket "Decision: the memory bank structure contract" (david/agent-harness issue 67), from the research on ticket 66. The flat index is capped per session and split evenly across banks, so a session today sees 46 of cortex's 226 in-scope memories, chosen by path order, not relevance; cortex gains about 30 memories a day into the same 28 folders, and its largest folder alone is too big for any flat list. The harness renders the bank index in **tiers**, every cap enforced when something is written and never by cutting at read time: **T0**, one line per bank, always; **T1**, orientation, up to 5 memories of at most 600 bytes each and 1,500 bytes per bank, always; **T2**, root breadcrumbs, one line per declared scope folder with a one-liner of at most 100 characters, at most 40 lines, always; **T3**, a folder's index of at most 40 lines (K = 40), expanded whole or not at all when the folder is relevant; the whole render at most 150 lines and 20 KB, inside Claude Code's 200-line, 25 KB limit with room for its own entries. **A pointer may replace a group; a line is never cut from a group.** A bank collapses to its bank line only when it has no relevance signal, and the registry refuses attaching banks whose fixed tiers would exceed 8 KB for an account and repository. Relevance ranks pin, then repository identity, then entity match, then recent use, ties by fewer lines. When a folder outgrows 40 lines it is nested one level into **topics**, authored by a person or agent from clusters the harness proposes; the write that would make the 41st line is refused with the existing topics; the root never lists topics. The session-independent tiers (bank lines, orientation, breadcrumbs, expansions by repository identity or registry pin) are written to the per-project `MEMORY.md`; expansions that depend on the session (entity match, session pin, recent use) go into the run's instruction layer, because Claude Code shares one `MEMORY.md` across every worktree of a repository.

## Considered options

- A flat index with a larger cap, or a priority order that fills until the cap: rejected; both still drop lines past the cap.
- K = 30: rejected as the default; it needs a second nesting level at ten times today's size. K per bank: rejected; two banks would render differently.
- Mechanical auto-splitting by name prefix: rejected; the clusters are good in some folders and leave half of others in groups of one or two.
- A per-run auto-memory directory for session-dependent expansions: untested and splits Claude's own memory writes; the instruction layer already exists per run.

## Consequences

- Tools: `memory_read` accepts a folder pointer and returns exactly the text the index would show inline (one-liner, topic breadcrumbs with counts, memory lines); a bare bank returns its root; no argument returns every bank's line. One pointer syntax everywhere: `bank:path/` for folders and topics, `bank:name` for memories. `memory_search` covers memories, folder and topic one-liners, orientation and entity aliases, takes a scope prefix, and reports how many of how many it returned. Counts are an invariant (children sum to the parent). A read ends with its folder pointer and count so reads lead sideways. The five-tool contract of ADR 0010 is kept.
- One validator runs at `memory_draft` (refuse with reasons), `memory_promote` (re-check against the bank's current main), the bank's CI on every pull request, and the BankService on `BANK.md` and registry changes. It refuses: a description outside 60 to 160 characters, equal to the name re-cased, or not unique in its folder; a body over 6,000 characters; a folder without a parsing `PROJECT.md` or `SYSTEM.md` carrying a `line:` of at most 100 characters and a `topics:` map; a folder or topic index over 40 lines after the write; a new declared scope folder that would make the bank's root breadcrumbs exceed 40 lines, unless the bank has re-tiered its root to its first scope level (each first-level folder then carries its own index of at most 40 lines, by the same rule); unknown scope labels or undeclared topics; a `BANK.md` without kind, purpose (at most 160 characters) and entities with aliases; an orientation list of more than 5 names or over its caps; repository scope entries that are directory names rather than remote identities. It warns when a description does not open with a trigger word, when two banks claim one alias, and when a `[[link]]` does not resolve.
- An index line is `name — description`; the bank, folder path and file template sit once in the section header.
- Orientation facts are written fresh as short pointers to the long memories; the orientation list in `BANK.md` changes through a reviewed pull request by default, and a per-bank setting lets a user auto-merge memories and decisions if they choose.
- Bringing cortex and brandsolidate onto the contract (nesting the five over-cap folders, fixing two unparsable `PROJECT.md` files, adding `line:` keys, topics, kind, purpose, entities and orientation, migrating 187 directory-name scopes to repository identities) is part of the feature's build, not a separate ticket.
- Amended by ADR 0037: root breadcrumbs are one per project or area holding memories, grouped under a header per org, and the org header is the pointer that may replace its group.
