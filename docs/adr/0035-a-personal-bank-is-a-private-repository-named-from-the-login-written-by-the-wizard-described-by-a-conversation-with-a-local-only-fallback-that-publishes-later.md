# A personal bank is a private repository named from the login, written by the wizard and described by a conversation, with a local-only fallback that publishes later; the generated index file is dropped

Decided 2026-09-25 on the map ticket "Personal bank flow: repo naming, creation, local-only fallback, second machine" (david/agent-harness issue 45), on the templates of ADR 0034. Artemis creates a bank on the desktop from a prototype-era form, keeps a token per bank, regenerates an `INDEX.md` on every landing that runs read as their index, and has no local-only bank. **The card proposes a name from the login**, `<login>-memory`, editable (cortex is what David would type), private, under the user's own account on the primary forge with no owner picker; the display name is the repository name. **The wizard writes the manifest and the skeleton deterministically**: `BANK.md` from the personal template with name, kind, a purpose of "<name>'s memory", the user as the first entity, the scope and write keys and the shared body; the folder skeleton with a first org and project from the wizard's questions, each with its `PROJECT.md` carrying `line:` and `topics:`; the bank's own home folder for orientation; a README; committed as the first commit through the ForgeService, which creates the repository and pushes. **The describe conversation** (the LLM step of ADR 0019) then authors the orientation memories, up to five short pointers, and completes the entity list with aliases from what the user says; its detection is `BANK.md` valid on main with every orientation name existing. **The local-only fallback is a real bank**: a git repository under the environment's data directory with `write.land: commit` and no review path, follow-ups kept as files in an `issues/` folder until a tracker exists, the card saying the bank lives on this machine only; when a forge account exists the Memory bank pane offers **Publish**, which creates the private repository, pushes, switches landing to pull request and offers to move the `issues/` files into the tracker, nothing happening on its own. **The registry entry** is read-write, enabled, every account, every repository, and the default write target for each account on the environment that has none; auto-merge of memories on. **Joining from another environment** is pasting the URL into its Memory bank step or ticking Same on every environment, which pushes the registry entry and lets each environment clone with the forge account matched by origin (ADR 0020); a stored per-bank token is offered only on a host with no account, and then appears on the Key manager step's Move stored tokens card (ADR 0028). **`write.merge` in `BANK.md` states the bank's own rule**, memories auto-merging while orientation, decisions and `PROJECT.md` status changes wait for review, written by the template and changed by pull request; the per-bank registry setting of ADR 0013 is a per-user override on team banks and mirrors the manifest on a personal one, the BankService applying whichever is stricter. **The generated `INDEX.md` is dropped** (David): runs start from the rendered breadcrumb trail and `memory_read`, the forge shows folders, the `index:` keys leave the templates, and the migration removes the file and its keys from the two banks already in use, cortex (David's personal bank) and brandsolidate (the team bank of the Brandsolidate brands). **Health**: done when the bank's remote verifies with the account's credential (or, local-only, the repository exists), `BANK.md` on main passes the validator, its orientation names exist and the registry entry is enabled; needs attention on an unreachable remote, a refused credential, a manifest failing validation (naming the rule) or a landing that failed part way; skipped with no bank, the card saying what is lost.

## Considered options

- A fixed repository name, or an empty field: rejected; a second personal bank on one forge would collide, or one more decision would sit at setup.
- No bank without a forge, or a local bank with no publish path: rejected; days of memory would be lost before a forge is connected, or moving it would be a manual push.
- The conversation writing the manifest and folders, or forms writing everything with no conversation: rejected; a manifest a model got wrong on day one, or a bank starting with no orientation.
- Read-write for the default account only, or every registry field asked: rejected; a second account's drafts would land nowhere, or four questions for a default that is nearly always the same.
- The merge rule in the registry only, or in the manifest only: rejected; a team bank would merge differently per teammate, or a user could never loosen a bank they own.
- Keeping the generated `INDEX.md` for people browsing the forge: not chosen; David dropped it.
- A per-bank token always: rejected; the drift ADR 0012 removed would return.
- Done once the repository exists: rejected; an invalid manifest would stay green.

## Consequences

- The memory-banks spec (issue 90) carries the create flow (name proposal, private repository, first commit), the local-only kind with `write.land: commit`, the `issues/` folder, Publish, the registry defaults, join by URL and the Same tick, the merge-rule precedence, the removal of `INDEX.md` and its keys, and the health check; the Set up spec (issue 88) holds the Memory bank card; the team bank flow (issue 46) reuses the create, join and health rules.
- Chosen defaults for review: the first org and project come from two wizard questions ("what do you call your own work" and "the first project"), preset to `personal` and the primary repository's name; the home folder is `personal/memory-bank/`; the README is the template's body rendered without placeholders; a local-only bank's `issues/` files carry the same "done when" shape as tracker issues so Publish can move them; Publish is refused while a landing is in flight.
- Fog: a personal bank on a forge other than the primary; two personal banks per user.
