# The Skills step shows honest catalogue cards, ticks nothing, probes a URL for its skill folders, learns the root-skill rule, lists trusted repositories, and syncs six-hourly

Decided 2026-09-25 on the map ticket "Skills step: catalogue presentation, always-on default, tracked repos, pull on launch" (david/agent-harness issue 43), which ADR 0016 re-scoped onto the skill set of ADR 0009 with the catalogue living in this repository. The 2026-09-22 catalogue research found that neither repository the old wizard meant to suggest works with a default folder (Matt Pocock's skills sit two levels down; unslop's `SKILL.md` is its repository root, which no folder value reaches), that licences belong to folders rather than repositories and that unslop's MIT grant has no LICENSE file and no named holder, and that a catalogue entry must carry its repository, folder, title, pitch, licence with where it was declared, skill count, per-skill list and an always-on hint, never applied on tick; Artemis syncs tracked sources behind runs at most every fifteen minutes with a forced Pull now. **The catalogue renders a card per entry**: title, pitch, skill count, a tick to track; expanding shows each skill's name, description and invocation kind (model and slash, or slash-only); **the licence line reads differently by where the licence was declared**, plain for a LICENSE file and with a caution glyph and the note for a licence found only in a README or a SKILL.md with no named holder; the always-on hint is a separate suggestion line with its approximate size ("about 1.5k tokens on every run"); a fast-moving repository says so; the twenty-source limit is stated on the card. **Nothing is ticked and nothing is always-on until the user acts**: once a source is tracked, a hinted skill's row carries an always-on switch labelled with the size and the accounts it applies to, the default account preselected and the others as chips, since always-on is per account (ADR 0009). **Sources sync at environment start, every six hours and on Pull now per source, never before a run** (David: skills change slowly; memory banks are what must stay fresh, and they keep their own before-run sync); each source row shows its branch or pin, last-synced and the commit; a pinned source never syncs until unpinned. **The reader learns the root-skill rule**: a folder whose own `SKILL.md` exists is itself one skill, named after the last path segment or the entry's name, so unslop and every other one-skill repository can be tracked, and the catalogue's unslop entry is tickable with its caution. **Adding by URL probes the repository**: the environment shallow-clones it, with the forge account matched by origin for a private repository (ADR 0020) and anonymously otherwise, lists every folder whose children hold `SKILL.md` files and the root when it is itself a skill, each with its count, and the user ticks one or more, each becoming a source with branch (default) or a pin; a repository with no skill folder says so instead of adding a source that yields zero. **Trusted repositories are listed and revoked on the Skills step** (David's choice over the Permissions pane): repository identity, trusted when and by which client, and Revoke, under the note that trust also admits the repository's project settings and hooks; the gate itself is asked in the session the first time. **Health**: done when every tracked source synced without error within the cadence and the environment's own skills directory is readable; needs attention on a source that failed to sync (authentication, repository gone), a source that now yields zero skills ("the layout moved", with the folders found), or more than twenty sources; skipped when nothing is tracked and the own directory is empty, never forced; a re-run offers Pull now on each failing source.

## Considered options

- Compact rows with the licence behind a link, or rows opening a details sheet: rejected; the licence caveat the research insists on would be hidden or a click away.
- Unslop tracked and always-on by default, or a confirm dialog on every tick: rejected; every other user would pay the tokens they did not choose, or a dialog would greet every tick.
- Artemis's fifteen-minute before-run sync, pull on launch only, or a per-source interval: not chosen; David set start, six hours and on demand, runs never triggering a skills sync.
- Vendoring unslop into the own directory, or leaving root skills for later: rejected; updates would stop, or the one skill David runs everywhere would stay untickable.
- A URL plus a folder field with a default, or the root assumed: rejected; wrong by default for most repositories, or broken on categorised ones.
- Trusted repositories on the Permissions pane, or in both places: not chosen; David wants them where skills are, once.
- Done only with a tracked source, or done meaning acknowledged: rejected; a person with only their own skills would be nagged, or sync failures would hide in notices.

## Consequences

- The skills spec (issue 89) carries the root-skill rule with a test, the probe that lists skill folders, the six-hour sync with Pull now and pins, the per-account always-on and per-environment disable events, the trusted-repository list and revoke, and the catalogue's validation; the Set up spec (issue 88) holds the cards, the copy and the health check; the memory-banks spec (issue 90) keeps banks' own before-run sync.
- Chosen defaults for review: an already-tracked catalogue entry shows ticked and links to its source row, and unticking removes the source after one confirm, its skills leaving every account; the same URL with different folders is separate sources; per-environment disable and per-account always-on are chips on the skill row; the Codex and OpenCode notes about instruction channels arrive with their milestone-2 adapters; a CI job in this repository shallow-clones each catalogue entry and checks its skill count, so a re-layout is caught before a user finds it.
- Fog: the planning-mode suggestion strip (ADR 0009); an upstream pull request giving the Pocock set its own readiness sidecars.
