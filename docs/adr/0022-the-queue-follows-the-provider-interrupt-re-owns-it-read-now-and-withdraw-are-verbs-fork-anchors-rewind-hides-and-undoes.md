# The queue follows the provider and falls back to the environment; interrupt re-owns it; read-now and withdraw are verbs; fork takes an anchor; rewind hides and can be undone; stop keys are per client

Decided 2026-09-24 on the map ticket "Decision: fork, rewind and read-now for queued messages from every client (M1)" (david/agent-harness issue 152), opened on David's instruction that fork, rewind and read-now work everywhere in milestone 1. Today a message sent during a run goes straight into the SDK's streaming input, so the provider folds it in at its next tool boundary or runs it as a turn of its own; nothing can withdraw it, "read it now" is a bare interrupt that trusts the CLI to keep its queue, the turn the provider then opens has to be adopted by the server (the 2026-09-18 transcript-reset bug), rewind cuts the conversation with no undo in the desktop, and the terminal UI has no fork command. The SDK now forks from a chosen message, drops a queued message by id, and reports on interrupt what it still holds; its file checkpointing cannot be combined with the session store the harness uses (ADR 0015 spec, ticket 82).

**The queue follows the provider.** The adapter contract gains a `providerQueue` capability beside `fork` and `rewind`; the existing `mid-run steering` flag now means that the provider folds a queued message into the running turn, which presupposes a provider queue, so a provider with a queue and no steering reads its queue only when the turn ends. A send during a live run on an adapter with a provider queue (Claude) is handed to the provider with a harness-minted message id, recorded `queued`, and becomes `steered` when the provider folds it into the running turn or `delivered` when it reads it; on an adapter without one (the OpenAI-compatible adapter in milestone 2) the environment holds the message itself and starts the next run with the queue when the turn ends. Either way every queued message is a `message.sent` event with delivery `queued`, visible to every client in order. **Interrupt re-owns the queue**: the adapter interrupts with cancel, and every message the provider reports still queued returns to the environment's queue in its original order, so nothing runs twice and nothing is lost; the partial assistant output stays (the open item closes with `aborted: true` on `assistant.text`), and the run ends `interrupted` with cause `user` (a drain that stops a run keeps its own reason, `drained`). **Read-now is one verb on the session**, `runs.readNow`: interrupt, re-own, then start the next run with the whole queue merged in order; the run ends `interrupted` with cause `read-now` and the next `run.started` names the message ids it carries. **Withdraw is one verb per message**, `runs.withdraw`: cancelled at the provider by id where it holds the message, else removed from the environment's queue, recorded `message.withdrawn`; the text is written into the session's draft, a session field, so it appears in every client's composer, and edit is withdraw then send. **Fork takes an anchor**: `sessions.fork` carries the source id, a client-minted new id, an optional `atMessageId` naming a user message (the fork holds the history up to but excluding it, and its text becomes the new session's draft), an optional account (the hand-off on one environment, ADR 0015) and an optional title; without an anchor the whole session forks. The fork carries the source's title until the provider's summary replaces it, its tags, group and workspace, never its archive, pins or settle, and forking is allowed while the source runs, which keeps running. **Rewind is conversation only and can be undone**: `sessions.rewind` to a user message appends `session.rewound`, later items stay in the log and the projection hides them, the message's text becomes the draft, and `sessions.undoRewind` is offered until a run starts on the rewound session, after which the cut branch stays in the log as rewound, shown under a fold; rewind is refused while a run is live (`conflict`, `run_active`; the client offers stop-and-rewind as two commands), and a rewind to the first message is refused with `use_new_session`, on which the client starts a new session in the same workspace with the text as draft. Files are never restored. **Adapters**: Claude honours fork, rewind and the queue through the SDK (fork with `resumeSessionAt` and `forkSession`, rewind with `resumeSessionAt` and `resumeDropsTurn`, withdraw with the cancel-by-id control); the OpenAI-compatible adapter holds no provider session, so the environment forks and rewinds by replaying its own log and queues in the environment, always available; Codex is decided in its milestone-2 spec and absent with reason meanwhile; a client draws an absent verb dim with the adapter's reason, never hidden. **Keys are per client.** The terminal UI keeps the current map untouched: Esc interrupts, Ctrl+C interrupts a live run and quits when idle, Esc Esc opens the prompt picker, which now has two actions per row, Enter rewinds here and `b` branches here; `/rewind [n]` (n counts prompts back, default 1) and `/fork [n]` (bare `/fork` forks the end) do the same from the composer; on a user row under the transcript cursor `w` rewinds and `f` forks (`r` stays recall); `Ctrl+Enter` reads now; `↑` on an empty composer withdraws the newest queued message into the composer; after a rewind the strip shows "Rewound to <prompt> · /rewind undo" until the next run starts, and `u` on the rewound fold under the transcript cursor undoes as well; fork onto another account goes through `/handoff`'s picker on the new session. The GUI has the Stop button and a palette entry and **no stop key by default**: Esc stopped runs David never meant to stop, and Ctrl+C is copy everywhere else and is never bindable to stop. A **Keyboard shortcuts pane** in Settings lists the one named-action list with a terminal column and a GUI column, each binding stored with its client; "Esc stops the run" is a GUI row, off by default. GUI surfaces: Fork and Rewind on every user message, Read now and Edit on the queued row and the composer strip, Undo rewind, the fork-to-account picker. The three verbs join the terminal UI's parity contract and the milestone-1 done criteria (ADR 0017).

## Considered options

- A harness-owned queue everywhere, with steer as an explicit send: rejected; David wants the provider's own queue where it has one, so that Claude's mid-turn folding stays automatic, and the environment's queue only where the provider has none.
- Letting the provider run what it still held after an interrupt as its next turn (today, through the adoption hook), or dropping it: rejected; a turn the harness did not start, the transcript-reset class of bug, or lost messages on every stop.
- Read-now per message, reordering the queue on the fly: rejected; the queue's order is the user's.
- Fork from the end only, as the wire had it, or a fork that carries only workspace and account: rejected; today's fork already works from any message in one step, and a fork that loses its title, tags and group has to be filed again.
- Restoring files on rewind through harness-made per-turn snapshots in milestone 1: deferred to the fog; the SDK's checkpointing is unavailable beside the session store, and a snapshot per workspace kind is a workstream of its own. Rewind with no undo: rejected; one misclick would lose a branch.
- Fork and rewind only where the provider offers them, or harness-native everywhere: rejected; local models would get nothing, or a Claude fork would lose the provider's own history and cost carry-over.
- Ctrl+C as the stop key in both clients, or Esc on by default in the GUI, or Esc with a confirming second press: rejected by David; Ctrl+C is copy in the GUI, Esc in the GUI caused accidental stops, and a stop that needs two keys comes late.
- Removing Ctrl+C's interrupt role from the terminal UI so both clients agree: rejected; the terminal convention differs, the terminal UI's map is the existing one transcribed exactly, and Milo relies on it.

## Consequences

- The Claude adapter spec (`docs/specs/claude-adapter.md`) and the terminal UI spec (`docs/specs/tui.md`) are amended in the same change; the GUI spec (issue 84) inherits the surfaces and the Keyboard shortcuts pane; the settings information architecture (issue 48) places the pane.
- New wire: `runs.readNow` and `runs.withdraw` at `runs:drive`; `sessions.undoRewind` at `runs:drive` beside `sessions.rewind`, which gains the `run_active` and `use_new_session` refusals; `sessions.fork` gains `atMessageId` and `session.forked` carries the anchor; `message.withdrawn`, `message.requeued` and `session.rewind-undone` events; `run.ended` gains a cause on `interrupted` (`user`, `read-now`); `assistant.text` and `assistant.thinking` gain `aborted: true` when an interrupt cut the item; `runs.send` answers where the message is held (`provider` or `environment`) instead of a steer-or-queue verdict; `run.started` names the queued message ids a read-now run carries; the `providerQueue` capability.
- The client runtime's `projections.runs` exposes the queue per session and the rewound state; `runs:drive` calls never queue in the outbox (ticket 80), so a withdraw on an unreachable environment fails at once with `unreachable`.
- A fork's message ids are the fork's own; a rewind or withdraw names ids from the session it is issued on.
- Fog: per-turn workspace snapshots so rewind can restore code; subagents' own queued messages.

## Amendment: visible history is copied at fork (#242)

Decided 2026-09-28 by David on #242: **copy at fork**. In the transaction that creates the fork and appends `session.forked`, the environment records the source's visible items before the requested anchor, or its whole visible transcript without one. The event's `history` seed holds the source title, the requested anchor's text, the items and their run summaries. Clients show it under one folded "Forked from <source title> at <anchored prompt>" row; no "at" for an unanchored fork. Deleting or purging the source does not remove or rename that copy. The extra log size per fork is accepted.

The snapshot carries the same `forked` item, including its seed, so replay, bounded catch-up and compaction show the same row. A fork of a fork flattens the carried history into its one new fold; rewind-hidden items are excluded. Partial assistant output visible during a live source run is frozen in the copy. Copied ids are provenance and read-only, never targets of commands on the new session. The provider continuation's inherited anchor and its history check (#236) remain independent of the visible copy's requested anchor.

## Amendment: milestone-1 Client parity proof (#1191)

The switch-over specification's phase-D decision (2026-10-02) makes these behaviours part of both Clients' parity contract:

- Fork at a user-message anchor while the source Run continues. The anchor's text becomes the fork's draft; title, tags, Group and Workspace carry, archive, pins and settle do not. The copied conversation is folded and independent of later source changes or deletion (#242); copied ids are read-only provenance.
- Rewind hides later conversation, never restores files, and offers undo rewind until another Run starts. A live Run refuses rewind; explicit stop-and-rewind remains two commands.
- Read-now consumes the whole unread queue in order exactly once, including provider input re-owned after interrupt and subscription replay. Withdraw returns unread text to the Session draft; delivery makes a late withdraw refuse.
- The TUI keeps Esc interrupt, Ctrl+C interrupt while live or quit while idle, Ctrl+Enter read-now, empty-composer Up withdraw, user-row `w`/`f` and `/rewind undo`. A fresh GUI leaves Runs live on Esc and lets Ctrl+C copy; Stop and palette stop interrupt, and Ctrl+C is never a stop binding.
- Absent Adapter verbs remain visible, dim with reasons. Drive commands refuse immediately while unreachable; they never wait in the outbox. Fork retains its existing organisation-command outbox semantics.

`/undo` and `/check` share runtime actions and projections and appear in both slash menus. File undo restores an agent file change and never calls `sessions.undoRewind`; `/rewind undo` restores conversation visibility only. Printing and listing are terminal-only stdout/pipeline/exit forms and add no GUI Session verb. The obsolete conditional phase-D deferrals are superseded: printing is #1180, listing #1181, runtime/TUI file undo #1185 and GUI file undo #1186, runtime/TUI Workspace checks #1189 and GUI checks #1190. Absent `fileUndo`/`workspaceChecks` flags stay absent with reasons until their handlers work.

Executable evidence lives in the Clients' `fork-rewind`, `queue` and stop/shortcut renderer cases, plus the client runtime's paired real-WebSocket fork case, observing public projections and recorded typed calls against scripted Claude behaviour. These cases do not certify a live signed-in SDK or machine defaults: signed-in Claude/keychain acceptance remains #217 and deployed-machine acceptance #1194. Known Adapter defects #299 and completions queued-turn following #1082 remain related, owned issues; this proof neither closes nor duplicates them.
