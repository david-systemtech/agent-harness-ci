# The Key manager step keeps the credential for unattended re-login, mints a child token per run from ticked policies, injects by default, and moves stored tokens into references

Decided 2026-09-25 on the map ticket "Key manager step: installer buttons, environment injection, and the standing prompt text" (david/agent-harness issue 42), which ADR 0016 re-scoped onto the registry, injection and orientation of ADR 0011 and the Managed tools of ADR 0026. The key-manager pane today is desktop-only, verifies a connection against the provider's own lookup, holds one credential per connection with no re-login, injects nothing into runs, and has no prompt beyond a generated paragraph; the 2026-09-22 CLI research found that OpenBao and Doppler need no login command once their variables are set, that `bao token lookup` is the one command proving a token and `bao status` distinguishes sealed by its exit code, and that a names-only secrets list is the one Doppler check that proves the whole path without returning a value. **The step has four provider tiles** (OpenBao or Vault, Doppler, 1Password, Bitwarden Secrets Manager) and a sign-in form per provider: OpenBao takes an address, an optional pasted CA kept as bytes and one of AppRole (role id and secret id), userpass or token; the others take a token. **The environment keeps the credential entered**, sent once in the add call and stored in its vault (a keychain on a desktop, a 0600 file on a headless machine, never on the wire again), and logs in, renews and re-logs in on its own, so a routine at three in the morning never waits on a person; Sign out deletes it. **Runs get a token minted per run, scoped by the policies the user ticks.** For OpenBao the step lists the policies the connection's login holds and the user ticks the ones runs receive, preset to all of them with a one-line warning when any grants write, so narrowing to read-only is one untick rather than a second credential; each run gets a child token with those policies and a TTL of the run's life, revoked at run end, and routines and bots get the same under their own overrides. Doppler, 1Password and Bitwarden tokens are scoped where they are created and are injected as they are, the card saying to create a read-only one. **Injection is on by default**: a signed-in connection injects into every run on the environment unless an account, routine or bot overrides it; the card says so in one line beside the switch, and the orientation block tells the model the key manager is reachable. **Each connection's CLI is a Managed tools row** on the card with Install or Update. **A Move stored tokens card** lists every forge account and bank still holding a stored token (ADR 0020): once per connection the user sets a base path where the harness keeps its secrets, suggested from the provider's conventions and editable; each item shows its target path beneath it (`<base>/forge/<slug>`, `<base>/bank/<name>`) with a Move button that writes the secret, reads it back, swaps the source to a reference and deletes the stored token; Move all appears once the base path is set; a manager whose token cannot write says so and offers Copy the value for a manual paste. **Health**: done when every connection verifies within the fifteen-minute cadence (token lookup for OpenBao, a names-only secrets list for Doppler, whoami for 1Password, a project list for Bitwarden) and its CLI is installed at or above the minimum ADR 0026 declares; needs attention on an invalid or expired token (Sign in again), an unreachable address, a sealed OpenBao (its exit code 2 read as sealed, not unreachable), or a CLI missing or below minimum (Install or Update); skipped when no manager is connected, never forced; the card says the harness resolves its own references over the provider's API without the CLI, so forge and bank credentials keep working when only the model's read path is missing.

## Considered options

- Storing only the derived token and asking a person to sign in again on expiry, or storing AppRole and tokens but never a password: rejected; unattended runs would lose their vault at expiry, and userpass would become attended-only.
- Injecting the connection's own token as it is, or a separate run token the user mints by hand: rejected; a bypass run would hold whatever the human can write, or every environment would need a second credential made by hand.
- A missing CLI as a mere badge, or one undifferentiated amber state: rejected; the model's read path is the point of the step, and a sealed server, an expired token and a missing binary need different fixes.
- Moving every stored token at once to harness-chosen paths, or no migration at all: rejected; the user would lose control of where secrets land, or stored tokens would linger forever.
- Deny-all injection by default, or a parked prompt on the first run: rejected; the step exists so the model finds its keys, and the prompt would always be answered yes.

## Consequences

- The key-managers spec (issue 91) specifies the provider interface with login, renew and child-token minting, the vault record per connection, the per-run token lifecycle, the Move operation with its read-back verification, the CLI minimums and verify commands; the Set up spec (issue 88) holds the card, the tiles, the policy ticks, the Move card and the health copy; the Forges step (ADR 0020) and the bank flows point at the Move card for stored tokens.
- Chosen defaults for review: the bulk copy to other environments carries address, CA, method and policy ticks, never the credential, the target environment asking for it once; the step generates no prompt of its own, since the orientation block carries the standing rule (ADR 0011); the terminal UI shows the step's summary and pointer; several connections per environment are allowed, one per provider address; suggested base paths are `harness/` on the first KV mount for OpenBao, a `harness` config for Doppler, a `harness` vault for 1Password and a `harness` project for Bitwarden.
- Fog: a read-only secret tool for shell-less models (ADR 0011); rotating an injected child token mid-run for runs that outlive its TTL.
