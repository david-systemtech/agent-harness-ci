# Spec: Claude adapter, the adapter contract and the completions surface

Milestone 1 (Switch-over), phase A (the spine). Written 2026-09-23 from map ticket 82 of `david/agent-harness`. Decisions it implements: ADR 0015 (the adapter contract, environment-owned provider processes, the served adapter retired, the completions surface with client-tool passthrough), ADR 0009 (the instruction channel, skills through a plugin directory, the `project` settings source behind the trust gate), ADR 0018 (accounts as environment-owned directories, environment-driven sign-in with the SDK-bundled binary, identity from auth status, the session store, one auto-memory directory per repository, the three stripped variables), ADR 0019 (a minted session is an ordinary session), ADR 0006 (modes, ceilings, prompts as events), ADR 0002 (the log holds transcripts), ADR 0017 (phase, placeholder name), with rules that also cite ADR 0001 (opaque unknown kinds), ADR 0005 (usage pooled by identity), ADR 0007 (drain, prompts surviving a restart), ADR 0011 (the orientation block) and ADR 0016 (the step registry), and the Resolutions of tickets 28, 29, 40 and 51. It builds on the environment-service (ticket 78), session-state (79) and client-runtime (80) specifications on main and re-decides none of them. Peers read: Artemis at 443cf2e (the adapter seam, the environment composer, the Claude adapter, the plan-usage read, sign-in on both paths, the completions handlers, the headless host's tests), the core port audit, the Claude Code and Hermes inventories, the Agent SDK reference and session-storage pages, the CLI reference and the headless page. The product name is the placeholder `agent-harness` throughout.

## Problem Statement

Every Claude run David starts in Artemis is one turn of a process the run owns, so a process dies with the window that started it, a turn pays a cold start unless the last one is still holding work, and a routine on the headless server gets a different host around the same adapter. The audit found the seam sound and Electron-free, with four faults around it: every query passes an empty settings list, so a repository's own instructions, hooks and rules never load; the adapter is one 6,136-line file; three of its types live in the desktop's IPC contract; and the plan gauge is read by name lookup on an experimental SDK method. Accounts share history and memory only through a script of nine symlinks nobody runs on the server, and an account has no identity, so one login on two machines is two gauges. Sign-in is a copied command on the desktop and a driven subprocess on the server. The completions surface, which is how the Hermes bots bill on David's subscriptions, marks a caller's `tools` as honoured and never reads them, so Hermes's memory, skill and cron tools never run; any token may ask for bypass; a disconnect interrupts the run; and a quiet stream looks like a dead socket.

## Solution

One adapter contract on the environment, with the Claude adapter as its first implementation. An adapter declares what it can do and how its credential is scoped, and turns a run into transcript events that go into the environment's log and nowhere else; sessions resume, fork and rewind through it; plan usage carries an account identity so the laptop and SYSTEM-SERVER show one gauge for one login; models come with tiers; commands are listed from the provider; standing instructions and always-on skills ride the provider's own instruction channel; tool servers are built per run; and a permission prompt is a parked event any client can answer. Claude's per-conversation process belongs to the environment: started on the first run, reused by the next, kept through a client's disconnect, drained for an update, stopped after thirty idle minutes. Accounts are directories the environment adopts or owns, signed in by the environment itself with the SDK's bundled binary. Transcripts reach any account's process through the SDK session store, auto memory is one environment-owned directory per repository, and a trusted repository's own settings load. The completions surface keeps its OpenAI shape on the same port, authenticated by client-session tokens under their ceiling, and turns a caller's tools into real tool-call round trips, so Hermes runs its own tools again.

## Implementation Decisions

Every rule cites its decision; a rule marked chosen default was left open by the tickets and is listed again under Further Notes.

### Modules and ownership

- The **contracts package** gains the transcript event vocabulary and the per-session snapshot shape; the `runs`, `accounts`, `models`, `commands` and `providers` registry entries with scopes; the account, plan-usage, model catalogue, sign-in state and completions schemas; the settings keys below. The three types the audit found in the IPC file (run suggestion, send response, delegated-work row) land here as transport-neutral schemas (ticket 28).
- The **environment package** gains the **adapter host** (adapter registry, provider-process pool, permission broker, tool-server factory, the instruction composer's seam, the SDK session store, the account store, the sign-in director) and the **Claude adapter**, split along the seams the audit named (ADR 0015): options, process, turn, mapper (pure), history, titles, the config-directory queue (serialising the SDK's standalone helpers, which read the config directory from the process environment), plan usage and sign-in. The **completions surface** is a module of the same package on the same port as the WebSocket.
- The contract is an in-process interface of live objects, as in Artemis; it never crosses the wire. The vocabulary and the methods below do.

### The adapter contract

An adapter provides (ADR 0015, ticket 28):

- **A capabilities descriptor**, static: interactive prompts, partial messages, a provider queue (`providerQueue`: the provider holds messages sent during a turn; absent, the environment holds them and reads them when the turn ends, ADR 0022), mid-run steering (the provider folds a queued message into the running turn; presupposes `providerQueue`), resume, fork, rewind, session listing, subagents and their transcripts, provider titles (read and write), transcript delete, plan usage, live model listing, commands listing, image and file input, the instruction channel kind (`system-prompt-append`, `developer-instructions`, `prompt`, none) with its character cap, and the mode set it maps. Every optional method pairs with a flag; the host refuses a call the flag does not cover with `invalid_request`.
- **A credential spec**: the config-directory variable, the credential variables it strips and never sets (the three of ADR 0018), the sign-in, status and logout argv, and a parser from status output to `{signedIn, authMethod, email, orgName, subscriptionType, error}`. A run's environment is the host environment with the provider's credential, backend-selection and storage variables scrubbed and the account's directory variable layered on top (Artemis's composer, ported as is).
- **`createRun`**, taking a resolved input (session and run ids, account directory, workspace and repository identity, model, effort, mode, the composed instruction text, the resume, fork or rewind target, the factory's tool servers, the trust decision, the prompt with attachments) and returning a run: an event stream consumed once, lossless, ending with exactly one end event on every exit path; `send` (steer or queue, with a message id), `withdraw` (a queued message by id, through the provider's cancel-by-id control), `interrupt` (with cancel: the result names the message ids the provider still held, which the host re-owns into the environment's queue, ADR 0022), `answerPrompt`, `stopTask`, `dispose`, `release`. The host is the only consumer and appends each event through the scoped append function and nothing else.
- **Sessions**: list, resume, fork, rewind, read a subagent transcript, delete a transcript; **titles**: read the generated title, write a user title. **Plan usage** per window with an **account identity** (provider plus email, and organisation when present), so the client runtime pools by identity (ADR 0005, ADR 0018). **Models** with a family and an ordinal tier the adapter supplies plus effort levels, a live listing flagged `live` when the provider can enumerate, else the static list flagged as such. **Commands** for an account and workspace, without spending tokens. **An adoption hook** for turns the provider opens on its own; the host registers them as runs of the same session (ticket 28).

The host supplies the scoped **append**; the **tool-server factory** (per run, closing over account, workspace and session: memory tools, browser, the completions surface's client-tool server); the **instruction composer** (ADR 0009: the four layers, a bot's persona, always-on skills and the orientation block of ADR 0011, composed once on the environment for every run origin; in phase A only a session's own instructions and the orientation block exist); the **permission broker**; the **process pool**.

### The transcript event vocabulary

Stream kind `session`, stream id the session id, the environment spec's envelope. Types the session-state spec flags `list` are marked.

- `run.started` (`list`): run id, account id and identity, model, effort, the clamped mode, workspace, origin (`client`, `routine`, `completions`, `provider`), prompt message id (and the queued message ids a read-now run carries, ADR 0022), resumed-from or forked-from.
- `message.sent`: message id, text, attachments (kind, name, size; bytes staged on the environment, never in the log), delivery (`prompt`, `steered`, `queued`); `message.delivered` when a queued message is read; `message.withdrawn` when one is taken back (its text goes to the session's draft, a session field); `message.requeued` when an interrupt returns one to the environment's queue (ADR 0022).
- `assistant.delta`: a batch of text or thinking fragments for the open item, flushed every 100 milliseconds or 512 bytes (chosen default); `assistant.text` and `assistant.thinking` close the item, with `aborted: true` when an interrupt cut it short so the partial text stays in the snapshot (ADR 0022). Deltas are ordinary events; the snapshot holds settled items only and a client applies deltas to the open item.
- `tool.started` (tool call id, name, input, agent id and parent call when nested, title), `tool.updated`, `tool.ended` (status `ok`, `error` or `cancelled`, output, duration); `command.ran` for a slash command.
- `prompt.raised` (`list`): prompt id, kind (`tool`, `plan`, `question`), tool call id, the provider's payload, the mode at the time; `prompt.answered` (`list`): decision and who answered (a client session, the unattended rule, the denylist, the TTL sweep; a routine's prompts are answered by the unattended rule). The permissions workstream owns the decision vocabulary, the TTL and the denylist; this one owns the events and the broker.
- `tasks.changed`: the delegated-work ledger as rows. `usage.reported`: tokens, cost, context window per model; `plan.limit`: a rate-limit verdict with window and reset.
- `session.provider-linked` (the provider's session id, on first init), `session.forked` (with the anchor message id when the fork took one), `session.rewound` (to a user message id; later items stay in the log and the projection hides them), `session.rewind-undone` (only before a run starts on the rewound session; afterwards the cut branch stays hidden under a fold, ADR 0022).
- `run.ended` (`list`): reason (`completed`, `error`, `interrupted`, `disposed`, `drained`), cause on `interrupted` (`user`, `read-now`), error, usage snapshot, duration, turn count, result text.

The **snapshot** carries `{summary, runs, items, openPrompts}`: items are user messages, assistant text and thinking, tool calls with updates folded, prompts with state, plans, commands and subagent rows; an unknown kind is opaque (ADR 0001). Subagent transcripts are read on demand, not logged (chosen default).

### Wire methods

Scope `runs:drive` unless stated; every mutating method takes a `commandId`.

- `runs.start`: session id, text, attachments, optional model, effort and mode; account, workspace and defaults come from the session (session-state's `sessions.create` delegates account, model and mode validation to this module). The mode is clamped to the connection's ceiling and the clamp recorded on `run.started` (ADR 0006). `unavailable` while draining; `conflict` reason `run_active` (send is the way in) or `account_unavailable`.
- `runs.send` (on a live run the message is queued and the result says where it is held, `provider` or `environment`; whether it is later steered into the turn or delivered at its end is reported by events, never at send time; on an adapter without `providerQueue` the environment holds it and starts the next run with the queue when the turn ends), `runs.readNow` (session id: interrupt with cancel, re-own what the provider still held, start the next run with the whole queue in order), `runs.withdraw` (message id: cancelled at the provider where it holds it, else removed from the environment's queue; `not_found` once read), `runs.interrupt` (re-owns the provider's still-queued messages into the environment's queue, never drops one; idempotent on an ended run: a no-op that re-owns nothing) and `runs.stopTask` (idempotent on a finished task). ADR 0022. `runs.answerPrompt` (prompt id, decision): the first answer settles the prompt; any later answer, on a live or an ended run, is `conflict` reason `already_answered`; an unknown id is `not_found`.
- `sessions.fork` (scope `sessions:write`): source id, client-minted new id, optional `atMessageId` (a user message: the fork holds history up to but excluding it and its text becomes the new session's draft; without it the whole session), optional account id and title; creates the record through session-state, carrying the source's title until the provider's summary replaces it, its tags, group and workspace (never archive, pins or settle), and marks the first run a fork; allowed while the source runs (ADR 0022). Forking onto another account is the hand-off on one environment (ADR 0015); across environments is milestone 2. `sessions.rewind` (session id, user message id; scope `runs:drive`, a chosen default, since it changes what the next run does rather than a summary field), recorded as `session.rewound`; `conflict` reason `run_active` while a run is live; a rewind to the first message is refused with `use_new_session` and the client starts a new session with the text as draft; files are never restored. `sessions.undoRewind` (session id; `runs:drive`) until a run starts on the rewound session, recorded as `session.rewind-undone` (ADR 0022). `sessions.subagentTranscript` (scope `read`).
- Scope `read`: `accounts.list`, `accounts.probe` (the ambient directory: present, signed in, identity), `accounts.signin.get`, `accounts.usage`, `accounts.handoff.recommend` (the ported threshold, load and recommendation functions over cached readings, so every client shows one offer), `accounts.refresh`, `models.list`, `commands.list` (account, workspace), `providers.list`.
- Scope `admin`: `accounts.adopt`, `accounts.add` (label; creates an owned directory and starts a sign-in), `accounts.relabel`, `accounts.remove` (with `deleteDirectory`, refused on an adopted account), `accounts.signin.start`, `accounts.signin.code`, `accounts.signin.cancel`, `providers.processes.list`, `providers.processes.stop` (chosen default).
- Settings keys through session-state's `settings.get` and `settings.update`: `accounts.defaultAccount`, `accounts.defaultModelFamily`, `accounts.defaultEffort` (ADR 0018; preset by the Account step to the highest tier at `high`), `providers.processIdleMinutes` (preset 30, ADR 0015); all four under the Account step's registry entry (ADR 0016).
- Notices on `environment.subscribe`: `account.updated`, `signin.updated`, `usage.updated`; the client runtime refreshes its request cache on them.

### Environment-owned provider processes

One Claude process per session, owned by the pool (ADR 0015). States: `starting`, `idle` (no turn), `busy` (a turn running), `parked` (a turn waiting on a raised prompt), `stopping`, `stopped`. The first `runs.start` on a session starts it, the next reuses it, a client disconnect changes nothing (ADR 0006). It stops when idle for `providers.processIdleMinutes` with no held work (a live background task or a registered schedule holds it, Artemis's retention rule), on `session.deleted`, on `providers.processes.stop`, or on drain. A process parked for the same idle time is stopped too: its run ends `interrupted` with cause `parked`, the prompt stays raised, and an answer later takes the resume path below (chosen default). On drain the host refuses `runs.start`, lets running turns finish up to the cap ADR 0007 sets, stops every process and reports to the launcher; a run cut by the cap ends `drained`. On startup a recovery sweep appends `run.ended` (`interrupted`, cause `restart`) for any run without an end event; its prompts stay raised (ADR 0007) and an answer given later starts a run that resumes the session and delivers the decision (Further Notes, item 7). Cold start after a stop is by store resume; no pre-warmed process in phase A (chosen default).

### The Claude adapter, ported after the audit's fixes

- **SDK and binary**: the pinned Agent SDK (0.3.280 or later; the store needs 0.3.234) with its bundled Claude Code binary, which also runs sign-in and status. The user's own `claude` is never spawned for runs.
- **Options per run**: workspace as `cwd`, `projectConfigRoot` for a worktree's checkout; model, effort; `permissionMode` from the harness mode (same names; bypass with the SDK's explicit allow flag); the `claude_code` preset with the composed instruction text as `append` (ADR 0009); `settingSources` `['project']` when the repository passed the trust gate, `[]` otherwise, never `user` or `local` (ADR 0009, ADR 0015; excluding `local` is a chosen default, so the CLI's own permanent approvals never leak in); `strictMcpConfig` on, so only the factory's servers load; `plugins` with the account's skill-set plugin directory (ticket 89); `settings` carrying `autoMemoryDirectory`; `sessionStore` always, with `resume`, `forkSession` or `resumeSessionAt` as the run asks; partial messages on; `canUseTool` wired to the broker; `CLAUDE_CODE_PROJECT_DIR_NAME` set to the harness session id so a resume never depends on the working directory; the bundled executable path.
- **Mapper**: Artemis's pure translation, extended for the vocabulary, with deltas batched. **Process**: Artemis's prompt pump, permission table, task ledger and settle grace, moved into the pool's process object; the turn is the run.
- **Plan usage**: a control-channel read on an unsampled query under the account's directory, through a tolerant lookup over `usage`, `getUsage` and the experimental name, degrading to unavailable on a rename and re-checked against the pinned SDK before build; in-flight reads shared; readings aged out after six minutes (Artemis's number); `plan.limit` verdicts fold in. Every reading carries the identity.
- **Titles**: a user title is mirrored through the SDK's rename after commit, best-effort (session-state spec); the generated title is reported after a run ends when the store-backed listing exposes it (verify first), else no provider title in phase A. **Identity**: from `auth status --json` after sign-in and on each status read; the run's `accountInfo` cross-checks it, and a mismatch is recorded as `account.updated` with a warning. **Modes**: `acceptEdits`, `plan`, `auto`, `bypassPermissions`; `default` and `dontAsk` are not offered (ADR 0006). Containment is passed when the permissions workstream sets it.

### Queue, read-now, fork and rewind on the Claude adapter (ADR 0022)

Claude declares `providerQueue`, `fork` and `rewind`. A mid-run `send` pushes an `SDKUserMessage` with the harness message id as its `uuid` onto the streaming input, as Artemis does; delivery is observed from the CLI's echo (`user_message_uuids` on the turn's first reply) and reported `steered` when it lands inside the running turn, `delivered` when a queued turn opens with it. `interrupt` sends the SDK's interrupt with `cancel_queued`, and the ids it reports still queued are re-owned by the host as `message.requeued`; a turn the provider opens on its own is still adopted through the adoption hook, but after ADR 0022 the host never expects one from an interrupt. `withdraw` uses the cancel-by-id control (`cancel_async_message`); if the provider reports the message already consumed the call is `not_found`. Read-now's next run passes the queue as the run's prompt messages in order. A fork resumes the source's provider session with `forkSession` and, when an anchor is given, `resumeSessionAt` set to the entry before the anchored prompt; the fork's provider ids are its own (the SDK remaps them). A rewind resolves `resumeSessionAt` to the entry before the user message and `resumeDropsTurn` when everything after it belongs to that one turn, as Artemis's `resolveRewindPoint` does; the SDK's file checkpointing is never enabled, since it cannot be combined with the session store. The build session verifies the cancel-by-id control and the interrupt's still-queued report on the pinned SDK before either is relied on; absent, `providerQueue` is declared false and the environment holds the queue for Claude too.

### The account store

Stream kind `account`: `account.adopted`, `account.added` (a directory under the environment's data directory), `account.identity-set`, `account.status-changed` (signed in, signed out, expired, unreadable; appended only on change), `account.relabelled`, `account.removed`, `account.directory-deleted` (owned directories, on the explicit second choice). Record: id, provider, label (preset to the email, unique per environment ignoring case), directory kind (`adopted`, `owned`) and path, identity, status with checked-at, created-at. One account per identity per environment: a sign-in yielding an identity already held is refused with "already added as <label>" and the new owned directory is deleted (ADR 0018). Status is re-read when the Account step or Accounts pane opens and at most every fifteen minutes otherwise, and carried into the orientation block (ADR 0011).

### Sign-in and status through the bundled binary

The **sign-in director** runs one sign-in per environment (ADR 0018): `accounts.signin.start` spawns the bundled binary with `auth login`, `CLAUDE_CONFIG_DIR` at the account's directory and the three credential variables stripped, stdin a pipe, stdout read incrementally. States: `starting`, `awaiting-code` (the verification URL published as `signin.updated`), `submitting`, then `done`, `failed`, `expired` (ten minutes) or `cancelled`. `accounts.signin.code` writes the code from any client; a second start is refused naming the account that has the floor; `done` triggers a status read and `account.identity-set`. The exact fallback command (POSIX and PowerShell renderings, the directory quoted) is part of the sign-in state, so every client shows it. Subscription only: `--console` is never passed; a Console user runs the fallback with it (ADR 0018). If the bundled binary does not run `auth login`, the managed tool `claude` is the fallback executable, chosen once per environment and recorded.

### The SDK session store and auto memory

The environment implements the SDK's `SessionStore`: `append`, `load`, `listSessions`, `listSessionSummaries` (folded with the SDK's helper inside `append`, serialised per session), `delete` (cascading to subkeys and the summary), `listSubkeys`. Entries are opaque provider state, so they are not events: they live in a `provider_transcripts` table beside the log, keyed by the harness session id, purged with the session's tombstone. This is the chosen reading of "over the environment's log": the log holds the events clients read; the store holds the entries the provider reads back. Every run passes the store; from a session's second run onward the run resumes from the store, which is then the durable copy, and the SDK deletes the temporary directory it ran in; a fresh session's first transcript file stays in the account's directory, written by the CLI as it always does. Resume on another account works because the SDK seeds that temporary directory with the credentials of the directory the run names, which ADR 0018 relies on and the build session verifies first. **Auto memory**: one directory per repository under the environment's data directory, keyed by repository identity (else the workspace path), passed through `settings`, shared by every account (ADR 0018); the Carry over step copies an adopted directory's per-repository memory into it (ticket 51).

### The permission broker

`canUseTool` hands each request to the broker, which appends `prompt.raised`, holds the deferred answer, and settles it on the first `runs.answerPrompt` from any client session with `runs:drive`, on the unattended rule, on a denylist match, or on the TTL sweep, appending `prompt.answered` with who answered (ADR 0006). Plan approvals and questions are prompts of kind `plan` and `question` on the same path. Dispose of a process denies every prompt it holds in memory but leaves a raised prompt raised in the log (ADR 0007); a later answer is `conflict` reason `already_answered` only once `prompt.answered` exists.

### The completions surface

Kept for programs (ADR 0015, ticket 29), on the same port as the wire.

- **Routes**: `POST /v1/chat/completions`, `GET /v1/models`, `GET /v1/models/{id}`; other OpenAI paths answer `501` with a sentence.
- **Authentication**: `Authorization: Bearer <client session token>` from a pairing of client kind `program` (added to the environment spec's kinds; chosen default) with scopes `read`, `sessions:write`, `runs:drive` and a ceiling set at pairing. `401` unauthorized, `403` scope, `503` draining.
- **Model ids**: `<account label slug>/<model or family>`, the slug slash-free; `GET /v1/models/{id}` matches the rest of the path, so an id from the listing is fetched as is; a bare id resolves to the default account; `/v1/models` lists every signed-in account's catalogue with `agent-harness.account`, `family` and `tier` beside each id.
- **The extension namespace** is `agent-harness` (the ADR 0017 placeholder rename), with `artemis` accepted as an alias until the switch-over ends, the namespaced key winning when both are present (ticket 29). Fields: `sessionId`, `permissionMode`, `systemPrompt` (append-only, 200,000 characters, after the environment's composed instructions), `alwaysOnSkills` (accepted and reported as ignored on the first chunk until ticket 89 lands, then honoured through the skill set), `forkSession`, `rewindToMessageId`, `attachments`, `thinking` (effort; `reasoning_effort` is its alias), `workspace` (a directory the environment has, else a scratch workspace per session), `attended` (default false), `after`, `ignoreUnsupported`. Browser fields return with the browser workstream.
- **`permissionMode`** is clamped to the connection's ceiling and the clamp reported as `agent-harness.clamped` on the first chunk (ADR 0006). **Prompts**: a completions run is unattended unless `attended: true`, so prompts are answered by the unattended rule and recorded, never parked (ADR 0006); with `attended`, they park and any client answers.
- **Messages**: the trailing user message is the turn; system and developer messages append after the composed instructions; earlier messages ride as an "earlier in this conversation" preamble on a fresh session and are dropped on a resumed one (Artemis's rule). No session id means a fresh session; the response carries the session id in the namespace.
- **Client-tool passthrough** (ADR 0015): a caller's `tools` become an in-process SDK MCP server named `client` for that run, one tool per declared function with its schema. When the model calls one, the surface emits an OpenAI `tool_calls` delta (ids minted by the environment, names without the server prefix), ends the stream with `finish_reason: tool_calls`, and parks the handler. The follow-up request's `tool` messages are matched to parked handlers by `tool_call_id` regardless of session id, so Hermes's loop works unchanged; the handlers resolve and the same turn streams on. A parked handler expires after ten minutes (chosen default) with an error result to the model. `tool_choice: none` withholds the tools; `required` and a named choice are rejected, or ignored under `ignoreUnsupported`. The agent's own tools never appear as `tool_calls`; they ride `agent-harness.activity` on empty-delta chunks, as in Artemis.
- **Streaming**: OpenAI's chunk order; every chunk carries `agent-harness.seq`, the log sequence of the event it renders; an SSE comment every fifteen seconds while quiet (Artemis's pacing); a mid-stream failure is a final chunk, never a bare close. A disconnect does not interrupt the run (ADR 0006); a later request naming a session whose run is going attaches from `after` and its trailing message is a steer.
- **Parameters**: `max_tokens`, `stop`, `stream`, `stream_options` honoured; `response_format`, `temperature`, `top_p`, `seed`, `n`, `logprobs`, the penalties and `logit_bias` rejected with `400` unless `ignoreUnsupported`; `user`, `metadata`, `store`, `service_tier`, `parallel_tool_calls` ignored and reported (Artemis's policy).
- **Non-streaming** returns the whole message, with `tool_calls` when parked and `usage` from `usage.reported`. Every turn is an ordinary run on an ordinary session: logged, listed, tagged `completions`, under the same ceilings, denylist and instructions.

### Codex, as milestone 2 direction only

The contract is provider-neutral on purpose: the Codex rewrite connects to Codex's shared per-`CODEX_HOME` daemon as a pool entry keyed by home rather than by session, generates its protocol types from the pinned CLI, maps the four modes as ADR 0006 records and never sends `untrusted`, delivers the composed text through `developerInstructions`, passes the factory's tool servers through config overrides, and answers `requestUserInput` through the broker as kind `question`. Nothing in phase A builds it.

## Testing Decisions

A good test is a behaviour visible through the wire, the completions routes or the contract's own surface, asserted from a client's or the host's point of view; never the pool's map, the broker's table or a row, except at the two lower seams where the store or the fold is the behaviour.

- **Primary seam: the in-process environment with a scripted fake adapter.** The environment spec's helper (temporary data directory, loopback port 0, the thin typed client over a real WebSocket) with the contract satisfied by a scripted fake: a script of events per run, a stub status probe, a static catalogue with tiers, a usage reading with an identity. It is the fake the environment spec names, extended here. Through it: a run's events on the per-session subscription with the `list` patches session-state expects; a run surviving its client's disconnect and a second client attaching; steer, queue and interrupt; a prompt shown to two clients, answered once, the second answer refused `already_answered`; the unattended rule; fork onto another account; rewind; the recovery sweep after a stop and start; drain refusing starts and ending a cut run `drained`; the idle stop under an injectable clock and the hold for a live task; accounts adopted, added, relabelled, refused as a duplicate identity, removed with and without directory deletion; the sign-in state machine with the binary replaced by a scripted process (URL published, code accepted, expiry, cancel, one at a time); readings pooled by identity; the settings keys. Prior art: T3 Code's `buildAppUnderTest` and `withWsRpcClient` in `apps/server/src/server.test.ts` and its `integration/orchestrationEngine.integration.test.ts` with `TestProviderAdapter`; Artemis's port-0 helper in `runStreamClaim.test.ts`.
- **Adapter seam: the Claude adapter with the SDK transport scripted.** The SDK module is replaced with `vi.hoisted` and `vi.mock` as Artemis's `apps/server/src/host.test.ts` does: a fake query with a message queue and the control methods, `createSdkMcpServer` and `tool` returning inert descriptors, the session functions stubbed. Tests observe the options `query()` received (settings sources by trust, the append text, `strictMcpConfig`, plugins, the auto-memory directory, the store and resume fields, the environment with the three variables absent and the directory variable present) and drive SDK messages through the mapper: init, deltas batched, tool use and result, `canUseTool` parking on the broker, task notifications, a provider-opened turn adopted as a run, the result ending the run, the usage read through each name and its degradation, the process kept and released across turns. Artemis's `claude.test.ts` cases port with the vocabulary renamed.
- **Completions seam: the surface through the in-process environment with `fetch`.** A `program` pairing; `/v1/models` and the bare id; chunk order, `seq`, the heartbeat under fake timers, the failure chunk; the clamp; `sessionId` continuity, fork and rewind; system messages after the composed instructions; the passthrough round trip with the fake adapter scripting a client tool call (the `tool_calls` chunk, the finish reason, a follow-up with `tool` messages matched by id and no session id, the turn resumed, the expired handler); the `artemis` alias; parameter rejection and `ignoreUnsupported`; attach to a live run. Prior art: Artemis's `adapters/artemis/__tests__/endpoint.test.ts` against a real `node:http` server.
- **Lower seams**: the session store against in-memory SQLite with the SDK's published conformance suite, plus the purge on a tombstone; the mapper as a pure function over recorded SDK fixtures, unknown message types kept opaque.
- **Contract tests in the contracts package**: every method above has one scope; every `list`-flagged event has a patch schema; the vocabulary and snapshot schemas round-trip the JSON Schema export; the extension schema rejects a mode outside the four.
- **Framework**: Vitest; listener-binding files run serially. **Not tested here**: a live Anthropic account (the verify-first checklist), the Hermes deployment (phase D), containment.

- Delta batches every 100 milliseconds or 512 bytes as ordinary events; the snapshot holds settled items only; subagent transcripts read on demand.
- `settingSources` `['project']` under trust, `[]` otherwise, `local` never; `strictMcpConfig` always on; `CLAUDE_CODE_PROJECT_DIR_NAME` set to the harness session id.

- The `program` client kind with scopes `read`, `sessions:write`, `runs:drive`; completions runs unattended by default; the `artemis` alias until the switch-over ends; the ten-minute handler expiry; results matched by `tool_call_id` without a session id; a scratch workspace when none is named; `seq` as the log sequence; the fifteen-second heartbeat; a later request on a live run attaches and steers.
- The status-change event only on change; a duplicate identity deleting the new owned directory.

Things the build session must verify first, in this order:

1. **Session-store resume across two config directories**: a session started under account A with the store, resumed under account B with the same store; the run bills B, the transcript is whole, the SDK deletes its temporary directory. Then the same with `CLAUDE_CODE_PROJECT_DIR_NAME` set, from a different working directory.
2. **The bundled CLI runs `auth login` and `auth status --json`** from the SDK's platform package with stdin piped, printing a verification URL and taking a code; and the fields `auth status --json` prints. If `auth login` is absent, record the managed-tool fallback as chosen.
3. **The stable name of the SDK usage control method** in the pinned SDK's type declarations; put it first in the tolerant lookup.
4. **Whether `query()` inherits bare mode** in the pinned SDK or a later one, and the option that opts out; the adapter must run with OAuth, auto memory and plugins on.
5. **Whether a user-scope MCP server in the account's config directory reaches runs** with `strictMcpConfig` on; if it does, the finding goes to the permissions workstream and the factory must become the only source by another means.

7. Whether the SDK's deferred-tool path (`defer`, then resume) works through the SDK transport, so a prompt parked across a restart can be answered into a resumed run; otherwise the decision is delivered as the resumed run's first message.
8. Whether the store-backed listing exposes the generated summary and `renameSession` works on a store-held session; otherwise no provider title and no mirror in phase A.
