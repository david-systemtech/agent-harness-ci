# Spec: Terminal UI as the first client

Milestone 1 (Switch-over), phase A (the spine). Written 2026-09-23 from map ticket 81 of `david/agent-harness`. Decisions it implements: ADR 0004 (one client runtime, renderers are projections, the terminal UI in the server artefact, the parity contract, named shortcuts with existing defaults), ADR 0016 (the terminal UI shows the Set up summary with a pointer and can pair and set mode and containment itself), with ADR 0001 (every client remote, the bootstrap grant), ADR 0003 (no organisation state in a client), ADR 0005 (environment badge, composer order), ADR 0006 (mode, ceiling, containment, parked prompts), ADR 0018 (accounts per environment, a sign-in the terminal can drive) and ADR 0017 (phase, placeholder name). It builds on `docs/specs/env.md` (ticket 78: the wire, the bootstrap grant for a `tui` local client session, pairing), `docs/specs/session-state.md` (ticket 79: summary fields, the two subscriptions, sort rules) and the client-runtime specification on branch `specs/80-client-runtime` (ticket 80: the runtime the terminal UI renders from); none of that is re-decided here. Peers read: the surfaces port audit (section 1), the pi inventory (section 1, `pi-tui`), T3 Code at 96c4bfa0 (`apps/server/src/terminal`, `packages/contracts/src/terminal.ts`). The product name is the placeholder `agent-harness` throughout.

## Problem Statement

Milo works in the existing terminal UI all day and David opens it on SAMPLE-SERVER. It is 31,203 lines of Ink 7 and React, and the audit found the UI layer sound: no Electron import, a keymap written as data, 57 test files, a controller that drives runs through a ten-method `RunDriver`. Everything under it is wrong. It is a third in-process assembly of the engine that reads the desktop's data directory and profile store, so it works only where the desktop is installed and drifts from it on every change. Its pins are a third store of bare session ids in its own state directory; a pin made there never shows in the desktop. It has no groups. Archive is the provider's tag, which Codex cannot hold. It cannot start a run in a worktree or on another machine; both rows are drawn and refused. It repaints every frame whole because Ink's `incrementalRendering` was never switched on. Keys cannot be remapped. And it is installed and updated apart from the server it should match.

## Solution

`agent-harness tui` is the second entry point of the server artefact: one install gives `serve` and `tui`, and the terminal UI's version always matches its local environment (ADR 0004). It is a pure client. It holds no organisation state, runs no engine, reads nothing of the desktop's, and renders from the client runtime and nothing else. On first launch it finds the environment on its own machine through the bootstrap grant and asks for no code; if the service is stopped it offers to start it; another environment is paired by pasting a link or typing a code. The rail projects the session-list subscription: environments as headings, same-named groups merged with a badge per row, pins, the settled shelf, snoozed sessions, the archive, tags, a filter. The transcript projects the per-session subscription and streams as the run goes. The composer keeps every existing key, slash commands and `@` completion, now answered by the session's environment. Permission and question cards sit under the transcript, the parked-asks card gathers every environment's prompts, the status line shows run state and plan windows, and the account and model pickers are per environment. Set up is a summary with a pointer to the desktop window; pairing, mode and containment are commands the terminal issues itself. A pane shows an environment-owned pseudo-terminal. Every shortcut is a named action with its existing default key, remappable in a file, with a test that every existing default is present. An unreachable environment shows what was last seen, queues edits as pending and refuses runs.

## Implementation Decisions

### The entry point and the platform

- **`agent-harness tui`** is a verb of the same CLI as `serve` (ADR 0004, env spec). Flags: `--environment <name or id>` (preset: the last used, else the local one, ADR 0005), `--session <id>`, `-c` (the newest session whose workspace is the current directory on the local environment), `--cwd <path>` (a new session's workspace), `--keybindings <file>`. The existing `-p` and `ls` are not carried in phase A.
- The terminal UI is a **platform for the client runtime** (ticket 80) plus Ink components over its projections. It supplies: document storage as JSON files under the state directory (`$XDG_STATE_HOME/agent-harness/tui`, the platform equivalent elsewhere, `AGENT_HARNESS_TUI_STATE_DIR` overrides), secret storage as one 0600 file per token in a 0700 directory there (so several terminal UIs on one state directory never rewrite each other's tokens), a Node WebSocket factory, the system clock, a network signal that is always online and in the foreground, socket failures being the only evidence of the network and each connection's backoff ladder already answering them (chosen default; a terminal has no reachability or focus event, a signal gone offline on failures would park every retry with nothing to wake it, and the local connection is on loopback, which the signal says nothing about), client kind `tui` with label `<user>@<hostname>:<tty>`, a bootstrap-grant reader, and **no shell**: every shell member answers absent with reason `no-shell` (ADR 0004).
- The state directory also holds the keybindings file, prompt history, snippets and the `@` pick memory, all client-local presentation. It holds no pins, groups, archive or drafts; the session-state spec's ADR 0003 lint runs on this package.
- `--import-terminal-state` reads the detected local terminal source through the source reader before Ink mounts (ADR 0036, switch-over spec). History merges by timestamp/text occurrence within its retention bounds; only the selected local Environment's held Session ids carry. Snippet names already saved here win, and after-edit text fills unset local entries, inert until explicitly saved through `/check`. Valid records and per-canonical-source completion commit atomically; partial stores report scrubbed diagnostics and stay retryable. Pins and drafts remain on the Environment import path.
- The existing terminal chrome variables carry renamed: `AGENT_HARNESS_TUI_IMAGES`, `AGENT_HARNESS_TUI_NOTIFY`, `AGENT_HARNESS_TUI_NO_TITLE`, `AGENT_HARNESS_DIFF`; `AGENT_HARNESS_TUI_BACKGROUND` (`light` or `dark`) is new with the theme's colours (#392).

### First launch: local detection, service down, pairing

- The runtime reads the local environment's bootstrap grant file and exchanges it over loopback for a `tui` local client session with every scope and the top ceiling; several terminals may run at once since `tui` exchanges are not replaced (env spec). No code is ever typed for the local environment (ADR 0001).
- **Service down**: when the grant file exists but discovery does not answer, the local connection reports `service-down` and one line above the composer offers "The environment on this machine is not running. Start it? y/n". `y` runs the CLI's service start verb (the launcher workstream's, ticket 86; assumed `service start`, verify first) and the runtime polls discovery while it reports `starting` (ticket 80). With no service installed the offer is "install and start it". The offer also stands with no grant file when a service is installed but stopped, or when the local environment is remembered from an earlier start: the environment removes its grant file when it stops cleanly, so a stopped service usually leaves none. With no grant file, no service installed and no paired environment, the screen is the pairing prompt.
- **Pairing** is `/pair <link>` or `/pair <address> <code>`: `connections.add` on the runtime, each typed failure (`expired-code`, `used-code`, `unreachable`, `protocol-mismatch`, `not-ready`, `different-environment`) one line (ticket 80). `/pair create`, with `admin` scope, calls `access.pairings.create` and prints the link, the short code and a QR in block characters (chosen default: a text QR is not a pixel gap). `/environment` lists connections with phase, version and "unreachable since" and offers enable, disable, remove, set primary and `sessions` (list and revoke client sessions), all runtime or `access.*` calls; each connection's card says its version and update and offers Update now, Drain and update now while busy work holds the pending update (#878), and a newer client's version (#827).
- Revoking this terminal's own client session from `/environment` counts `bye: revoked` before the reply as success (#1979): "Revoked this client. Pair again to reconnect." on a paired connection, or "Revoked this client. Try again to reconnect." locally. The result stays visible without re-listing through the revoked connection. Another session's revoke and real failures keep their existing lines.
- A protocol mismatch is rendered as the runtime reports it: update this client, or update the environment through the launcher's self-update when its flag is present (ticket 80, ADR 0007).

### The screen

The existing layout stands (audit section 1): a header (logo, environment chip, workspace), the rail on the left, and on the right the bottom-anchored transcript, the delegated-work strip, the checklist strip, the queued line, the open card (permission, question, picker, session preview, Set up summary or terminal pane), the composer, the status line and the activity line. Tab walks composer, rail, delegated strip, terminal pane when open, transcript, skipping stops not drawn (`nextFocus`; the pane is the one added stop), save the rail, which stays a stop under 100 columns (superseded by #145: with the focus it is drawn in the pane's place as "Sessions"). Under 100 columns the rail is hidden beside the pane and the picker replaces it. Layout is client-local presentation (glossary: Pane).

### The rail: a projection of the session list

The rail renders `projections.sessionList` and `projections.environments` (ticket 80); every row is a summary of the session-state spec.

- **Headings, in order**: pinned (merged across environments by `pinOrderKey` then `pinnedAt`); one heading per merged group (the session-state spec's merge and order rules, text from the primary environment); ungrouped sessions under their environment's name; the snoozed shelf with wake times; the settled shelf, folded; the archive, folded. Fold state per heading name is the allowed presentation key `collapsedHeadings`.
- **Every row**: environment badge (colour, icon, two-letter abbreviation, ADR 0005), title, activity glyph (`idle`, `starting`, `running`, `parked` with count), tags, a `pending` marker while an outbox entry is unconfirmed, and a dim style with "unreachable since" on the heading when its environment is down.
- **Row keys** dispatch the session-state commands: `a` archive or unarchive, `p` pin or unpin, `d` delete (confirmed once; `/restore` within the grace), and the added `s` settle or unsettle, `z` snooze (picker: an hour, this evening, tomorrow morning, next Monday, a typed time; absolute UTC on the wire), `t` tag, `g` group (a picker of merged headings plus new; `groups.create` on the session's environment first when it lacks the group, then `sessions.setGroup`), `Shift+↑` and `Shift+↓` move within the pinned block or the active list (`sessions.reorderPinned` or `sessions.reorderActive` with a key generated between neighbours) and answer absent with the reason in the shelves and the archive, which have no manual order (session-state spec). On a merged group's heading, `R` renames the group (a typed picker holding its name) and `D` deletes it (confirmed once), one `groups.rename` or `groups.delete` per member group, each on its own environment (#128's note, #752). These are chosen defaults that clash with nothing in the existing sidebar context; the drag gesture is the named gap, the semantics are not.
- **Filter and search**: `/` in the rail filters visible rows; `/search <text>` runs `projections.search` across environments (ticket 80) into a picker. Neither is server-side search.
- Enter on an environment heading starts a session there (ADR 0005): the composer shows environment, account, model chips in that order and `sessions.create` carries the client-minted id, the workspace and the chosen account, model and mode. The workspace in phase A is a `directory` path on that environment, chosen from a picker of the paths that environment's session summaries already carry, or typed; browsing an environment's directories and the other workspace kinds are the workspace-picker workstream's (85), and `/cwd` opens the same picker.

### The transcript: a projection of one session

- The transcript renders `projections.session` (ticket 80): streamed messages; tool calls folded as they are today (a run's finished calls as one count row, running and failed in full, a tool quiet three minutes turns amber); prompts and questions at the sequence of `prompt.opened` once answered (permissions spec); plans; delegated work as the strip; the cost line under each finished turn (tokens, dollars, plan-window deltas when the adapter reports them). An opaque event is one dim row naming its type (ADR 0001). A `cached` or `catching-up` marker heads the transcript until `synchronized` (ticket 80).
- The row verbs carry: `o` opens the file in `$VISUAL` or `$EDITOR` when the environment is local, else in the pager through `files.read`; `d` and `/diff` read `diffs.session` and `diffs.workingTree` through the user's diff filter; `x` interrupts the tool through the adapter workstream's method; `r` recalls the command. The pager (`Ctrl+O`) and `/export` work over the projection.

- **A run an update cut** (#452): `update-interrupted` stands at its `run.update-interrupted` sequence, in live replay and snapshots alike, as one muted transcript line. Both renderers use the runtime's `updateInterruptedText`: "Updated to 0.5.0 while this ran; continued", "... waits for your answer to the parked prompt", or "... waits for your next message: <reason>". Reasons read "the provider cannot resume this run", "the account changed or is signed out", "the mode changed", "the workspace is gone", "the session was deleted", or "the caller must retry the completions request". The item keeps the update id, target version, cut run id, outcome, reason and continuation run id; it stands through compaction and under a rewind's fold like any other item.
- **The environment's message** (#452): a `user-message` item keeps its event actor as optional `sender`; `sender.kind: system` names the environment, except `system:carry-over`, which records the import of a historical human message and keeps the person's rendering. The continuation's `system:updates` message is labelled "Environment", never "You" or "Your message". Older snapshots without a sender remain readable without inventing an actor. The terminal uses `· Environment: <text>` in place of the person's `▌`; the GUI uses a left-aligned bordered message labelled "Environment" with accessible name "Environment message". Transcript exports use "Environment" as the heading too.

### The composer

- The existing component with props from the runtime: `live` from `projections.runs`, `locked` with a reason from `capability`. The draft is a session field, debounced one second and dispatched by the runtime (ticket 80), so it follows the session between clients. History, snippets, paste chips, `Ctrl+V` images and `Ctrl+G` are client-local and carry as they are.
- As in the window, a single word beginning with `/` (including `/` alone and unfinished commands) is never saved as a draft, nor is a command this client answers with its arguments. A slash-prefixed message with words after the first, such as `/usr/bin is broken`, is saved. The terminal also excludes shell lines beginning with `!` or `!!`, which it executes itself.
- Sending dispatches the adapter workstream's start and send methods (`runs:drive`, never queued); a send during a live run is a queued message, held by the provider where it declares a queue and by the environment otherwise (ADR 0022), shown on the existing queued line in order until it is steered, delivered or withdrawn. `Ctrl+Enter` reads now (`runs.readNow`); `↑` on an empty composer withdraws the newest queued message (`runs.withdraw`, the action `composer.withdrawLast`, conditioned on an empty composer beside `composer.navigate` on the same key), whose text lands in the session draft and so in every client's composer, a real withdraw, where before only the text could be taken back. Attachments ride the send method's field (ticket 82).
- **Fork and rewind** (ADR 0022): Esc Esc opens the existing prompt picker with two actions per row: `picker.choose` (Enter) rewinds here (`sessions.rewind`) and `picker.branch` (`b`) branches here (`sessions.fork` with the row as anchor); `/rewind [n]` (n counts prompts back, default 1) and `/fork [n]` (bare `/fork` forks the end) do the same from the composer; on a user row under the transcript cursor `w` rewinds and `f` forks (`r` stays the existing recall). After a rewind the strip shows "Rewound to <prompt> · /rewind undo" until the next run starts; `/rewind undo` and `u` on the rewound fold under the transcript cursor both call `sessions.undoRewind`. A rewind while a run is live is refused; the picker offers stop-and-rewind as two commands. Fork onto another account goes through `/handoff`'s picker on the new session. Files are never restored; the picker says so.
- **Slash commands** carried with one rename: `/account` (was `/profile`; `/profile` stays a hidden alias), `/model`, `/mode`, `/resume`, `/attach`, `/copy`, `/export`, `/diff`, `/pin`, `/title`, `/asks`, `/timeline`, `/snip`, `/tasks`, `/usage`, `/handoff`, `/cwd`, `/new`, `/help`, `/quit`. Added: `/environment`, `/pair`, `/containment`, `/setup`, `/settings`, `/review`, `/archive`, `/group`, `/tag`, `/settle`, `/snooze`, `/restore`, `/search`, `/terminal`, `/files`, `/documents`, `/notices`, `/reload`, `/fork`, `/rewind`, `/routines` (#533), `/undo` (#1185) and `/check` (#1189), required in milestone 1 phase D (switch-over spec). An unknown `/command` goes to the agent as typed (the existing rule); the provider's own commands come from the adapter's commands query when its flag is present.
- `/handoff` in phase A opens the account picker for this session's next run on the same environment with each account's plan reading, as it does today; hand-off between environments is milestone 2 (ADR 0005), drawn absent-with-reason.
- `@` lists the workspace through `files.list` on the session's environment, scored by the fuzzy scorer; `/files [path]` opens the same listing as a browsable picker and Enter reads the file in the pager through `files.read`. `!` runs a command in an environment-owned terminal attached to the workspace and `!!` sends its output.

### Cards: permissions, questions, parked asks

- A parked prompt (permissions spec) renders as the existing card below the transcript: cursor on Deny, a bare Enter never authorises, `Tab` for a note, `Space` ticks options on a question, the blast-radius lines when the adapter supplies them. The answer is `permissions.prompts.answer` (`runs:drive`: never queued, re-sent with its command id after a mid-flight drop, so story 11 holds by the runtime's rule). `remember: 'session'` is the card's "for this session" row. The existing `e` and `s` keep their keys and answer absent ("rules are per session on the harness", permissions spec), drawn dim as `planned` rows were before.
- **Parked asks**: `/asks`, and `Ctrl+]` when more than one session is parked, open the existing asks card over `projections.runs`' parked list across environments, each row with badge and TTL countdown from server time; `y` and `n` answer in place, Enter opens the session.
- **Attention**: the runtime's attention events drive the `attention` module unchanged: title, bell or OSC notification after six seconds of an unanswered prompt or sixty after a finished turn with no key pressed, and the away summary. `projections.notices` shows on the activity line and stacks in `/notices`.

### Status, usage, pickers

- **Run info** (#655): `app.runInfo.toggle` (Alt+I) opens or closes the open session's latest run, live from `projections.session`'s `runs` and `policies`: who started it and whether attended, the resolved mode with its ceiling and clamp reason, containment with its mechanism and reason, account, model, effort, tokens by kind, cost and ending. The words are shared with the window's run info in the client runtime; a policy missed before catch-up says "not heard". The card wraps and scrolls with the pager's keys, closes with Esc or q and with the session, and says when no run has started.

- **Status line one**: badge, account, model and effort, mode, containment glyph, and at the right the plan windows from `projections.usage`, pooled by account identity (ADR 0005, ADR 0018). **Line two**: the run's activity, elapsed time, tokens, cost, key hints; or the existing yellow hand-off offer when the window is out and no run is live.
- `/account` lists `projections.accounts` for the session's environment with plan readings plus "add an account", which starts the sign-in the adapter workstream drives (ADR 0018: the environment publishes the URL, the terminal shows it and takes the code). `/model` lists `projections.models` with effort. Both are per environment (ADR 0001).
- `/mode` and `Shift+Tab` step plan, acceptEdits, auto, bypassPermissions clamped to the connection's ceiling; a mode above it is greyed with the ceiling named; the choice is `permissions.mode.set`, which returns the effective mode; bypass shows the permissions spec's sentence. `/containment` calls `permissions.containment.set` among off, workspace, workspace-no-network, greying unavailable levels with the probe's reason from `permissions.settings.get`. `/review` renders `permissions.review.list`.
- `/settings` is a generic editor over `settings.get` and `settings.update` (session-state spec): every key of the contracts settings schema under the label of the row it sits on (ADR 0027's row registry), rendered by type, read-only without `admin` scope; `/settings <row id>` opens on that row's keys alone, since the terminal UI needs no rail.

### Set up: the summary and the pointer

- Set up is a summary with a pointer to the desktop cards (ADR 0016, ticket 30). `/setup [environment]` renders `projections.setup`: one line per registered step with its label, glyph and state word, and its reason when it needs attention; skipped lines dim. With no name it uses the session environment. Snapshots and notices redraw it without a check; without the `setup` flag, opening it asks `setup.check` and says live updates are unavailable. While a step on the session environment needs attention the header reads "Set up on <environment>: N of M done, K need a fix (<step names>).", "1 needs a fix" for one, with M its registered steps; the card's closing line reads "Press Enter on a step to run its fix, or open Set up in the desktop app." (setup-copy.md §4.5 words both). Cached unreachable results say "This app cannot reach <environment> (since <time>)" and each says "This may be out of date: <environment> cannot be reached." Enter runs the line's first offered action; `picker.preview` (Space, remappable) previews its next action. Check again, Pull now, Restore, Update and Start service run here using the runtime's named plans; other actions point at the desktop. A tool's Update is offered only where `tools.run` is served and its managed-tool row offers Update, opening its terminal in the pane. After accepted writes issued here, Your machines is checked for pairing, Permissions for mode and containment, and Account for sign-in. The pointer names the desktop window in milestone 1, the browser tab from milestone 2.
- Steps the terminal completes itself are those whose writes are commands it already issues: pairing (`/pair`, Your machines), mode and containment (`/mode`, `/containment`, Permissions), a sign-in (`/account`, Account, ADR 0018). Their health re-reads after the receipt.

### Terminals, files and diffs: the vocabulary this workstream fixes

The env spec reserves scope `terminal` for these and leaves them to the renderer workstreams; the terminal UI is built first, so this workstream fixes the vocabulary in the contracts package and the environment's terminal module. The GUI (84) reuses it and may add optional fields, never rename. Every method takes scope `terminal`; mutating ones a `commandId`.

- **Terminals** are environment-owned pseudo-terminals with scrollback capped at 5,000 lines or 8 MiB (ADR 0004, T3 Code's `BoundedTerminalHistory`), attached to a session's workspace, outliving any connection. `terminals.open` (client-minted id, session, optional columns, rows and environment variables; the login shell in the workspace directory), `terminals.write`, `terminals.resize`, `terminals.close`, `terminals.list` (per session: id, opened at, size, exit code), and the stream `terminals.subscribe` (id, `afterSequence`; snapshot of the retained scrollback, then output chunks and `exited`). Output never enters the event log: a bounded in-memory history per terminal plus the subscription, gone with the terminal (chosen default; the log holds transcripts, ADR 0002). A session's terminals close on delete. Prior art: T3 Code's terminal manager, `NodePtyAdapter`, `OutputProtocol`.
- **Files**, read-only in phase A: `files.list` (session; `git ls-files --cached --others --exclude-standard` in a repository, else a bounded walk with the existing skip list; capped at 20,000 entries with `truncated`) and `files.read` (session, relative path, 2 MiB cap, `binary` flag). Paths never escape the workspace (`invalid_params`).
- **Diffs**: `diffs.workingTree` (session; unified diff of the workspace) and `diffs.session` (per file, from the runs' tool events); 8 MiB cap with `truncated`.

**The terminal pane.** `/terminal` opens or reopens a terminal for the session as a pane between transcript and composer, sized through `terminals.resize`. It is drawn from a **headless terminal emulator** (`@xterm/headless`, which pi-tui's tests drive) fed by `terminals.subscribe`, its rows rendered as Ink text with colours. With focus, every key is forwarded through `terminals.write` except the two `terminal` actions: `terminal.leave` on `Ctrl+\` (chosen default; twice sends a literal) and `terminal.scrollback` on `Ctrl+O`, which opens the retained scrollback in the pager. A reconnect resubscribes from the cursor and replays, so scrollback survives a blip. The environment owns the terminal; the pane only draws it, so this is not a pixel gap.

### The parity contract in practice

The contract is the wire (ADR 0004). In milestone 1 the terminal UI implements: sessions and every organisation command; runs (start, send, steer, queue, read-now, withdraw, interrupt, fork, rewind, undo rewind, status, usage; ADR 0022); permissions and questions (cards, parked asks, mode, containment, the review list); accounts, models and usage per environment, including a sign-in; settings (the generic editor); Set up as summary and pointer (ADR 0016's shape, not a gap); environment management (pair both ways, list, enable, disable, remove, revoke); the terminal pane, and files and diffs as pager views; documents (`projections.documents`: markdown read in the pager, a page or an SVG named with its path for the desktop window's preview, #427); an environment's update (its version, pending update and bundled Claude Code, Update now, Drain and update now (#878) and a newer client's offer, on its card in `/environment`, #827); delegated work and tasks. Whatever the runtime projects, the terminal renders. Milestone 1 phase D also requires shared `/undo` and `/check` actions/projections in both Clients (#1185/#1186 and #1189/#1190); file undo is separate from `/rewind undo`, which changes conversation visibility only. `-p` printing (#1180) and `ls` listing (#1181) are terminal-only stdout/exit surfaces (switch-over spec, "Phase-D commands and parity"; ADR 0022).

Workspace checks use `projections.checks` and `runtime.checks`, and the runtime's `checkWords` ("After-edit check: off for <workspace>." or "After-edit check: $ <command>", as the GUI says it): `/check` reads the directory command, `/check <command>` saves the text verbatim, `/check off` clears it and `/check now` runs it on the Environment. The shared Session projection supplies dollar-command rows and failure offers; `s` (Send failure) on an offered check row or Enter on an empty composer sends the failure explicitly; Enter on the row unfolds its output. Imported after-edit text remains inert until explicitly saved.

**Named gaps**, each filed as a `parity` issue when the build starts, David deciding (ADR 0004): the browser dock pane; the GUI's preview pane (a rendered web preview of the workspace, not the rail's session preview, which the terminal has); the drag gesture for reordering (semantics on `Shift+↑`/`Shift+↓`); images beyond the kitty, iTerm2, WezTerm and Ghostty protocols (drawn as `[image WxH · size]` elsewhere, as it is today); the pane grid (one session at a time, `Ctrl+]` switches). The documents pane is no gap: `/documents` lists the same projection, text in the pager (#427). A capability the environment reports absent is not a parity gap; it is the runtime's absent-with-reason line.

### Shortcuts: the shared action list, the defaults, the keybindings file

- **Named actions.** Every key is an entry in one shared list in the contracts package: id, context, default keys, one-line description, and `wired` or `absent` with a reason (ADR 0004). Ids are `<context>.<verb>` (prefix `row` is context `transcript`, `rail` is `sidebar`) and `command.<name>` for slash commands; contexts are the existing eight plus `terminal`, `asks` (the parked-asks card, whose keys were drawn on the card's hint line rather than registered as actions) and `confirm` (the one-line yes or no offers: service down, delete). Sigils typed into the composer (`/`, `@`, `;;`, `!`, `!!`) are syntax, not keys, and only their menu triggers are actions. The GUI's defaults for the same ids are its own column.
- **Defaults reproduce the existing terminal map exactly**: every row is one action with the same keys and context, every command a `command.<name>` with the same usage line; the table below is the transcription. A row the harness lacks keeps its keys as `absent` with its reason, drawn dim in the help overlay as `planned` rows were.
- **Bindings are per client** (ADR 0022): the terminal map is the existing one, Esc and Ctrl+C included, and the GUI keeps a map of its own with no stop key by default; the Keyboard shortcuts pane (GUI spec) shows both columns over this one action list.
- **`keybindings.json`** in the state directory (or `--keybindings`): a JSON object from action id to a list of key names as written in the table, read at launch and on `/reload`. An unknown id or key name is reported and ignored; a mapping giving one key to two actions in one context is refused whole with the clash named (an existing test rule made a runtime rule), save the one sharing the list allows: an action declared with a condition (`composer.withdrawLast`, on an empty composer) may hold a key beside one unconditioned action of its context, is asked first while its condition holds, and keeps its condition when remapped (the contracts' `keyClashes`; #231). `/help` shows the effective map with remapped rows marked.
- **The test**: a fixture holds the existing rows and commands as data; it asserts every fixture row has an action with the same keys and context, every command has its `command.<name>`, no two actions in one context share a default key but for a conditioned action beside an unconditioned one (the clash rule), and every id is in the shared list. This is ADR 0017's shortcut contract test.

## Testing Decisions

- **What a good test is**: a frame a person would see, produced by a key a person would press, asserted by row; never a component's state, a hook's value or a private map. ## Further Notes

Chosen defaults not decided on a ticket, for review:

- The `tui` flags; the state directory and its variables; the client label; a network signal from socket failures only; the QR in block characters.
- Rail actions `s`, `z`, `t`, `g`, `Shift+↑`, `Shift+↓`, and `R` and `D` on a group's heading (#752); `Ctrl+\` to leave the pane and `Ctrl+O` for its scrollback; the snooze presets; `/profile` as a hidden alias; the slash commands added, including phase-D `/undo` and `/check`.
- The terminal, file and diff vocabulary: scrollback 5,000 lines or 8 MiB, output never in the log, `files.list` at 20,000 entries, `files.read` at 2 MiB, diffs at 8 MiB, the login shell in the workspace, `@xterm/headless` as the pane's screen model.
- From the build of the vocabulary (#124): terminal commands are receipted like any command and append nothing (`changed: false`, the receipt's `sequence` the head it found), and each acts on the terminal once its transaction commits; their receipts are kept on a `terminal` aggregate named by the terminal id. A terminal id is a client-minted version 4 UUID, never reused on an environment (`conflict`, reason `exists`): not while the environment runs, and not across a restart while an accepted command's receipt names it (30 days). A session holds at most 16 terminals, running or exited (`conflict`, reason `too_many_terminals`), and an exited terminal's scrollback is dropped ten minutes after the exit by the environment's clock, leaving its exit code listed until it is closed: together the memory ceiling. A terminal whose shell exits stays listed with its exit code and scrollback until `terminals.close` or its session's deletion; writing to or resizing it is `conflict`, reason `exited`. `terminals.close` hangs the shell up (`SIGHUP`), kills it after three seconds if it lingers, and drops the terminal at once. Terminals do not survive a restart of the environment. Output is gathered 5 ms (or 64 KiB) into one chunk. A line of the scrollback cap is a newline, an unfinished last line counting as one; the oldest output is dropped whole-chunk first, then the head of the oldest chunk (cut on a UTF-8 boundary), and a cut chunk is never replayed, only snapshotted. The ring keeps at most 4,096 chunk records: past that the oldest is merged into the next (no text lost, the merged chunk snapshotted, never replayed), so newline-free output such as a spinner cannot pile up a record per read. A shell that fails to start after the open was accepted leaves the terminal exited with code -1 and `terminal.exited` cause `failed`, the error in its scrollback and the environment's log. The login shell's passwd entry may be missing (a container's arbitrary uid): the names then come from `USER`/`LOGNAME` or the uid, the home from `HOME`, and the shell is `/bin/sh -l`. `diffs.workingTree` answers `conflict`, reason `git_failed`, with git's `fatal:` line when git runs and fails (a failing required filter of the machine's config, a broken repository), and `repository: false` only when git says the workspace is in no repository. The login shell is the passwd entry's (`os.userInfo().shell`) with `-l` for sh, bash, zsh, dash, ksh, mksh, fish, tcsh, csh and yash, none for another; with none usable (empty, `nologin`, `false`, relative, not executable) `/bin/sh -l`; on Windows `powershell.exe`. The base environment is `TERM=xterm-256color`, `COLORTERM=truecolor`, `PATH`, `HOME` and `LANG` (the environment's own, else `/usr/local/bin:/usr/bin:/bin`, the passwd home and `C.UTF-8`), `USER`, `LOGNAME` and `SHELL` (the shell started), plus on Windows the variables it needs to run anything (`SystemRoot`, `USERPROFILE`, `APPDATA`, `TEMP` and the like); a client's variables go on top, at most 100. The pseudo-terminal is `node-pty` 1.1.0, an optional dependency pinned exactly: loaded lazily on the first terminal, so an install where it did not build succeeds, the environment still starts, and `terminals.open` is `conflict`, reason `pty_unavailable`; it compiles with node-gyp on Linux (CI's `node:24-bookworm` carries python3, make and g++) and uses its prebuilds on macOS and Windows, whose `spawn-helper` is given its execute bit if it lacks it. A workspace directory that is gone is `conflict`, reason `workspace_missing`. `files.list` answers its `source` (`git` or `walk`); the walk's skip list is the existing one: `.git`, `node_modules`, `dist`, `out`, `.tsbuild` and every other dot-directory, symlinks neither listed nor followed. `files.read` answers `path`, `size`, `binary`, `truncated` and `text` (null when binary); a path with nothing there is `not_found`, kind `file`, a directory `invalid_params`, reason `not_a_file`, and an escape `invalid_params`, reason `escapes_workspace` (drive-letter and UNC paths are refused on every platform). `diffs.workingTree` is `git diff` against HEAD (the empty tree before the first commit) with `--relative`, untracked files shown as new files by adding only them with intent-to-add to a scratch copy of the index, with a scratch object store that reads the repository's as an alternate (the user's index and object store are never written), `repository: false` outside a repository, and `conflict`, reason `git_unavailable`, where there is no git (`files.list` walks instead). Git runs hardened against the repository's own config, which an agent can write: `core.fsmonitor=false`, hooks pointed at nothing, no external diff or text conversion, a nested repository diffed by its commit alone (`--ignore-submodules=dirty`, `--submodule=short`: nothing runs inside it), and a scrubbed environment (a terminal's clean base, no `GIT_*` but the ones asked for, none of the environment's own variables). A clean, smudge or process filter the repository's own config names (its config, its worktree's, or a file either includes) is refused, not run: `conflict`, reason `git_filters_refused`, the filters named in `data.filters`, since the environment's git runs outside any containment (permissions spec, #212); a filter the machine's config names (system or global) runs, seeing only that scrubbed environment. `diffs.session` reads the session's recorded path when its directory is gone (its data is the log's) and names a file relative to the recorded or the real path, so a symlinked workspace names its files the same either way. The walk enters at most 20,000 directories. `diffs.session` folds the tool calls that ended `ok` of Claude's `Edit`, `MultiEdit`, `Write` and `NotebookEdit` per file, in first-changed order, each with the calls behind it; a hunk uses the tool output's `structuredPatch` (the SDK's tool result) when the output carries one, else it is built from the input with line numbers counted from the edited text, and a write shows its content as added. Both diffs cap at 8 MiB cut after a line.
- From the build of `terminals.open`'s look (#669): `terminals.open` is a prepared command. Before it decides, the availability watcher looks at the session's workspace within its 5-second bound (workspace-picker spec, "Missing workspaces"), so a directory on a network mount whose server is gone never stalls the environment, and the open is refused `conflict`, reason `workspace_missing`, when the look finds the directory gone or it does not answer in time. While the watcher's gate holds (two looks overdue) it looks at no other path, and the open decides on the session's mark as it stands. A `terminals.write`, `terminals.resize` or `terminals.close` of the terminal, or its `terminals.subscribe`, sent while its open is still looking waits for the open and is decided after it, as it would have been had the open not waited: a client may send them right after the open without waiting for its receipt. `terminals.list` does not wait; it lists the terminal once the open is decided. On Linux and macOS the shell's change into the workspace is made by the forked child, so it cannot stall the environment; on Windows the process is created with the directory from the environment's own thread, so a mount that dies between the look and the spawn may still stall it.

- Chosen defaults not decided on a ticket, from the routines build (#533):
  - **The card**: `/routines` lists `projections.routines`, each environment under its heading ("desk · 2 routines", and while it cannot be reached "· unreachable: as listed at <time>"), an environment that lists none one dim row. A routine's row is its name, "pending" while a command about it waits in the outbox, and its schedule in words (`describeSchedule`); the line under it its next firing or "disabled", what needs attention in words, the failure streak ("3 failed in a row"), then its live firing or last outcome, so what matters most stays in sight on a narrow card.
  - **The keys** are the `routines` context's, looked up before the picker's, which keeps the moves, Enter and Esc; a verb answers on a routine's row only, and the endpoints' keys only on the endpoints card.

  - **Run now** is `routines.runNow` through the outbox, which never queues it: "Running <name> on <environment> now.", refused at once "Not run: <environment> cannot be reached.", and `firing_running` "Not run: <name> is firing already." **Space** enables or disables through the outbox, the routine pending while it waits; a refusal at dispatch is one line, a later one its notice.
  - **Export** asks for the path, preset the name in lower case with hyphens and `.yaml`, resolved against the working directory with `~` expanded, and writes `routines.export` of that routine whole.
  - **History** is one row per firing or skip, newest first (when, outcome or skip reason, trigger, the due times it stands for, how long it ran); the entry at the cursor is drawn under the list: its kept text (a skip's detail), six lines at most, its pre-check in words with four lines of its output, and one line per delivery. Reaching the last entry reads the page before it.
  - **Edit** writes `routines.export`'s YAML to `routine.yaml` in a private directory and lends the terminal to `$VISUAL` or `$EDITOR`, as Ctrl+G does. A save the same as what was opened (white space at the end aside) or an editor that exits other than 0 sends nothing. A save is checked with `routines.checkImport`: its issues reopen the document; then a document whose mode is `bypassPermissions` asks once on the confirm line with the permissions spec's sentence, read from `checkImport`'s definition, or from the document's top-level `mode` line when the environment cannot be asked; then `routines.import` with `routineId`. An import refused at `yaml` (`invalid_params`) or for a name taken reopens it too.
  - **The issues as comments**: each is a line `# refused: <path>: <message>` over the line its path names, indented as that line, found by the document's block layout, since the client reads no YAML (routines spec, "YAML export and import"); a step not found, or a value written on its key's line (a flow map), puts it on the deepest line found, and a YAML problem goes over the line it names. The comments of the round before are taken out first.
  - **Offline**: an import dispatched while its environment cannot be reached, or that loses it before its answer, waits in the outbox, the routine pending ("Queued: <name> is saved once <environment> can be reached; until then it shows pending."); a refusal then is its `command-rejected` notice, never an editor opened later.

  - **`/routines endpoints`** lists the header's environment's `routines.endpoints.list` (name, URL, where its secret is, its last result). `a` asks for the name, the URL, then a pasted secret drawn as dots (Enter for none, or to keep the one held for a name that exists), and sends `routines.endpoints.set`; `t` posts `routines.endpoints.test` and says its status and time; `d` confirms, then `routines.endpoints.remove`: direct `admin` calls with a command id.
  - **`/routines test-precheck <name>`** finds the routine by name ignoring case, on the header's environment first, and runs `routines.testPreCheck` once, drawing what it found in words with twelve lines of its output and standard error.
  - **`/notices`** is a list: Enter opens the session a notice is about (a routine's firing, a parked prompt's session), else says the notice is about no session. A `routine-delivery-failed` notice is the runtime's to raise (#529); the activity line and `/notices` draw every kind.
  - **Tests**: `packages/tui/src/routines.test.ts` over scripted environments answering the routine methods (`packages/tui/test/routines.ts`, whose YAML is the contracts' codec, as the environment's), with an editor the test injects; `routines/document.test.ts` places the comments.
