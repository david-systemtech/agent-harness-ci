## Problem Statement

David uses skills in every session, and today they are treated as a file on each machine. The list of tracked repositories and always-on choices lives in one machine's data directory; the server keeps its own copies, and a served run's always-on skills cross as names, so a skill the server lacks silently adds nothing. A repository's own skills never reach a Claude run, since the bridge reads only the account's own directory, `~/.agents/skills` and tracked repositories, and every Claude run passes an empty settings list, so the repository's `CLAUDE.md` or `AGENTS.md`, where the Pocock skills expect their tracker to be "provided to you", never loads and its hooks never run (skills research, surprise 1). Always-on never reaches Codex, local models get no skills at all, and Codex skills are linked into its deprecated root. Nothing says whether a skill's inputs exist: the model reads prose and tells David to run a setup skill after the fact. The two repositories a setup wizard meant to suggest would add zero skills, one because its skills sit two levels down and the other because its `SKILL.md` is the repository root. Sources sync before runs every fifteen minutes. A skill can be switched off only by deleting its folder, since `skillOverrides` cannot reach the bridge plugin. Standing instructions live only in the desktop: routines and remote-bridge runs get none, the terminal UI gets none, a Codex account gets none, and a completions caller gets only what it sends (core audit, section 5). The one built-in instruction is deleted by switching it off.

## Solution

Each environment owns its skill set: repositories it tracks, synced at start, every six hours and on Pull now and never before a run; its own directory, which Carry over fills from the Claude Code directory; and a repository's own skills once David trusts that repository there. Adding a repository means pasting its URL and ticking the folders the environment found, a one-skill repository included. Every account gets one merged set, which Claude sees as a plugin; typing `/name` works in every client. A skill that needs something says so in a file beside it, or in an overlay the harness ships, and the composer shows "setup needed" with the failing check and its fix. Standing instructions are composed on the run's environment for every run, whoever started it: the orientation block and David's own instructions, the team bank's lines, the repository's own instructions once trusted, the session's, a bot's persona later, and always-on skills. Suggested instructions become owned copies that remember their origin and never change unseen. Trust is asked once per repository per environment, in the session, and listed with Revoke on the Skills step.

## Implementation Decisions

Every rule cites its decision; a rule marked chosen default was left open by the tickets and is listed again under Further Notes.

### Modules

- **contracts**: the skill-set schemas (source, member, origin, choice, readiness result), the sidecar's schema, the **catalogue** and the **overlay** as data modules with their contract tests, the skill-name rule and the source URL and folder rules as pure functions, the methods, events and notices below, the `instructions.orientation` settings key, and the Skills and Instructions registry entries.
- **environment**: the **skill-set service** (source store, syncer and snapshot store; own-directory reader; repository reader; materialiser; readiness evaluator), the **trust store**, the **instruction store**, the **composer** filling the host's instruction seam, and the **slash resolver** on the host's start and send paths. All git goes through the hardened runner (#124) and, for a forge origin, the ForgeService's credential helper (ADR 0020, #87).
- **client runtime**: the new reads through the request cache, refreshed on the three notices below, and `commands.copyToEnvironments`, the bulk edit.

### The skill set

- **Layers** (ADR 0009): each source's current snapshot; the environment's own directory; and, when the session's repository is trusted, the repository's `.agents/skills` and `.claude/skills` in the workspace directory and each parent up to the repository root (the scan Claude Code and Codex make), or for a workspace in a linked worktree, at its root or below it, the main checkout's root alone (David's decision on #998, below). A **member** is a folder holding `SKILL.md`, or a command file in the own directory's `commands/` (named by its file, described by its frontmatter; a skill folder of the same name in that layer wins, as in Claude Code); its files pass through untouched. A member's invocation kind is `slash-only` when its frontmatter sets `disable-model-invocation`, else `model+slash`, which is what **model-invocable** means below.
- **Name**: the frontmatter `name` when it passes the Agent Skills rule (1 to 64 of `a-z0-9-`, no leading, trailing or doubled hyphen), else the folder's name when that passes (for a root skill, the source folder's last segment, else the repository's last path segment), else the member is invalid. A member without a description is invalid (the Agent Skills spec; Codex refuses one). Invalid members are listed with their problem and left out; a name unlike its folder is a warning.
- **Precedence** for one name, highest first: the trusted repository (`.claude/skills` over `.agents/skills`, a nearer directory over its parents), the own directory, then sources, the earliest added first. This reads #23's list (sources, own directory, trusted repository) as layers applied in that order, each overriding those applied before it, as the Agent Skills guidance has project skills override user skills (chosen reading). A disabled name is left out whichever layers hold it. A shadowed member is listed with the member that shadows it.
- **Readable by runs**: the own directory, the snapshots and the generations below join the denylist's exemption from its data-directory preset, as the workspace roots do (workspace-picker spec, #132, #140), so a model can read a skill's files; snapshots are written read-only.

### Skill sources

- **Record** (ADR 0029): id, the URL as entered, its repository identity (the workspace-picker rule), the folder (`.` for the root), what it follows (a branch, null for the remote's default, or a pinned commit), its position, and who added it when. The URL passes the source URL rule (https, ssh or scp form; no credential, query, fragment or leading hyphen); the folder is relative with no `..`. At most twenty sources (`conflict`, reason `source_limit`); one per identity and folder (`duplicate`); the same identity with another folder is another source.
- **The reader** (the root-skill rule, ADR 0029): a folder holding `SKILL.md` is one member; otherwise each direct child holding `SKILL.md` is a member; nothing deeper is read, and no link leading out of the tree is followed. One reader serves sources, the probe, the own directory, repositories and the catalogue job.
- **Probe** (`skills.probe {url, branch?}`, ADR 0029): shallow-clones the branch through the harness's git, authenticated by the forge account for the URL's origin, anonymous without one, ssh by the user's keys (ADR 0020), and answers a probe id, the identity, branch and commit, the root when it is itself a skill, and every folder up to four levels down whose children hold `SKILL.md`, each with its members (name, description, invocation kind) and any licence file beside it; at most 2,000 directories are read, skipping `.git` and `node_modules` (the Agent Skills client guidance). A repository with no skill folder answers none, and the client adds nothing. A failure is `conflict`, reason `unreachable`, with a problem: `authentication`, `not_found`, `network`, or `git_failed` with git's `fatal:` line. The checkout is kept thirty minutes for an add to reuse (chosen default).
- **Add** (`skills.sources.add {url, folder, follow, probeId?}`, a prepared command whose fetch runs in `prepare`, env spec): reuses the probe or fetches, reads the folder, refuses `no_skills` with the folders found when it yields none, else appends `skills.source-added` and `skills.source-synced`.
- **Sync** (ADR 0029): every unpinned source at environment start, once the wire is open and off the startup gate; every six hours after (chosen: one timer, sources staggered); and on Pull now (`skills.sources.pull {sourceId}`, prepared, answering the outcome). Never before a run. One sync per source at a time, a Pull now joining one in flight: a depth-one fetch of the followed branch within sixty seconds (chosen default), then the folder exported at that commit into a **snapshot**, an immutable copy under the data directory. Outcome `ok`, or `failed` with the probe's problems or `layout_moved` (no members; the folders found). A failed sync leaves the last good snapshot current (chosen default). `skills.source-synced` is appended only when the commit, the members or the outcome change; each attempt's time is the source's status, kept outside the log.
- **Pin and remove**: `skills.sources.setFollow {sourceId, follow}` pins at the current commit or a named one (fetched), or unpins to a branch and syncs at once. A pinned source never syncs; Pull now on one is `conflict`, reason `pinned`. `skills.sources.remove {sourceId}` takes its members from every account. A snapshot no generation uses and no source holds current is deleted at start and hourly.

### The own directory and Carry over

- The **own directory** lies under the data directory with `skills/` and `commands/` (ADR 0018: the harness makes directories only there); `skills.get` names its path, so a terminal pane or an editor reaches it. It is read at each run's start and on `skills.get`, with no watcher. `skills.own.create {name, description}` writes a folder with a minimal `SKILL.md`; `skills.own.remove {name}` moves a folder to the data directory's trash for thirty days (chosen default). A manifest in its root, in the existing vendoring format (per folder: repository, path, commit, licence), gives its members' provenance (the skill-origin-from-mirror-manifest write-up); a source's manifest is read beside its folder or one level up.
- **Carry over** (ADR 0021): `skills.carryOver {accountId, dryRun}` (`admin`, prepared) reads the adopted account directory's `skills/` and `commands/` and, chosen default, the machine's `~/.agents/skills`, which today is bridged into every Claude run. A skill folder that resolves into a git working tree with a remote is offered as a source (the URL without credentials, the folder's path in the repository, its branch, or a pin at a detached `HEAD`) and not copied; any other skill folder or command file is copied, a name already present kept and reported; a provenance manifest beside an original is carried into the own directory's. The report counts copied, kept, offered and invalid, and lists subagents and plugins as not carried; the dry run answers it for the card (#88). Nothing in the adopted directory is created, linked or deleted.

### The trust gate

- **Key**: the session's repository identity; else its repository's main checkout path (both from the workspace-picker spec); else, chosen default, the workspace path. A scratch workspace has none and is never asked about.
- **Record**, on the `trust` stream: key, key kind (`identity`, `checkout`, `directory`), decision (`trusted` or `declined`), when, the client session and its label then, and the session it was asked in (ADR 0029: when and by which client). No record is undecided. `trust.decide {sessionId | key, decision}` and `trust.revoke {key}` (back to undecided) are `admin`, chosen default: trust admits hooks and permission rules that act outside modes and ceilings.
- **What it admits**: for Claude, the `project` settings source and `projectConfigRoot` (claude-adapter spec; a linked worktree's main checkout, so that checkout supplies its settings, hooks and native skills, #998), so the repository's `CLAUDE.md` (or `AGENTS.md` where Claude Code reads it), rules, settings (permission rules and hooks among them), `.claude/skills`, `.claude/commands` and `.claude/agents` load; and the repository's members join the skill set. Its `.mcp.json` servers stay out (`strictMcpConfig`), and its local files never load (no `local` source).
- **Asking** (ADR 0029: in the session): `trust.get {sessionId}` answers the key, the decision and what the repository offers: instruction files, members per root, commands, hooks by event, permission rules, subagents, and MCP servers marked not loaded. A client shows the gate while the decision is undecided and the offer is not empty. A run never waits for it: undecided runs untrusted, a decision takes effect at the session's next run (the spawn key already carries `trusted`, so a kept process is replaced), and a live run keeps what it began with. Unattended runs never ask.
- `trust.list` feeds the Skills step's list: trusted keys with Revoke, declined ones with Trust. Each reads "Trusted 5 Oct 12:43 by Desk window": the time where the client is, as Access words a pairing's, and the client session's label; its id waits under the row's Details disclosure, which keyboard and touch reach, never a native title (#1797, #1800).

### Choices: disabled and always-on

- `skills.setEnabled {name, accountId | null, enabled}` and `skills.setAlwaysOn {name, accountId, on}` (`admin`) append `skills.enabled-set` and `skills.always-on-set` (ADR 0009, ADR 0029). Null means the whole environment, which outranks an account's choice. Choices are keyed by name, so they survive a re-layout and apply to every layer holding the name; a choice for a name not in the set is inert and listed; choices naming a removed account are dropped.
- Nothing is always-on until the user acts (ADR 0029). Any member may be always-on; the Skills step shows the switch on catalogue-hinted members with the default account preselected, the pane on every member, each labelled with the body's size and an approximate token count (a quarter of its characters). A disabled member is never appended. An account whose adapter's instruction channel is `none` shows the switch dim with the reason (ADR 0030).

### Materialisation and the Claude mapping

- **The run's skill set** is resolved at each run's start and each commands listing from the account, the session's trust key and decision, the choices and the layers. Its **fingerprint** covers each member's name, kind, the path its link leads to, origin, snapshot commit and whether it is native and always-on for the account (#501), and the hidden native names; an unchanged fingerprint reuses its **generation**, a directory under the data directory holding a plugin manifest naming the plugin `agent-harness` (the placeholder, ADR 0017), `skills/<name>` linking to each member's folder and, for each command member, `skills/<name>` holding a `SKILL.md` that links to the command file (the pinned CLI skips a plugin's command file that is a link, #496), leaving out the **native** members: those in the roots the account's adapter declares it loads itself under trust (Claude: the repository's `.claude/skills`, which the `project` source brings, with the repository's own commands). Links are symbolic links, and junctions on Windows. Own and repository members are linked live, so an edit reaches the next invocation; source members point into their snapshot, so a sync never changes a running process's files. A generation no live process uses, no resolution holds current and none has resolved since the sweep before is deleted at start and hourly.
- **Claude** (ADR 0009, claude-adapter spec): the descriptor declares `.claude/skills` as its native root; the adapter passes the generation as its one local plugin and hides a disabled native member with `skillOverrides` `off` in the flag settings it already passes. The fingerprint joins the spawn key, so the first run after a change gets a fresh process resuming from the store, as changed instructions do (#138).
- **Contract changes**: the capabilities descriptor gains the native skill roots; `RunInput` gains the run's skill set (generation directory, fingerprint, every member with name, origin, invocation kind, whether native and whether always-on for the run's account, the native names to hide); `RunInput.trusted` comes from the trust store; `Adapter.commands` takes the skill set beside `{trusted}`, and the host passes both (paying #121's "until #89"); the adapter's `pluginDirectory` option retires; the adapter answers a member's invocation text.
- **`commands.list`** takes a `sessionId` in place of the account and workspace (its trust then applies) and answers entries of kind `skill` (every member, command members included: name, description, invocation `model+slash` or `slash-only`, origin, always-on, argument hint) and `command` (the provider's own, `builtin` flagged); the provider's listing of `agent-harness:<name>` and of native members is folded into the skill entries, and a member with `user-invocable: false` is not listed.

### Slash resolution

The host resolves a message whose text starts with `/<name>` or `/skill:<name>`, on `runs.start`, `runs.send`, `runs.readNow` and a completions turn, against the run's skill set (ADR 0009: `/name` is provider-neutral):

1. `/skill:<name>` names a member explicitly (pi's form, chosen default).
2. `/<name>` naming a provider built-in command stays the provider's; the member is reachable as `/skill:<name>` (chosen default: a skill never shadows a built-in).
3. `/<name>` naming an enabled, user-invocable member, command members included, becomes the adapter's invocation (Claude: `/agent-harness:<name>`, or `/<name>` for a native member) followed by the rest of the text.
4. Anything else passes as typed.

`message.sent` keeps the typed text and gains `skill {name, origin}` when the client run command or completions turn resolves it at send time; the adapter receives the rewritten text for that run. A queued message is resolved again against the skill set of the run that later reads it, which may pass it as typed after a member is disabled, or resolve a member enabled since the send. The recorded attribution remains the send-time resolution. Initial prompts from actor starts without slash preparation stay literal. A client's own verbs, such as the terminal UI's `/new`, win inside that client. Slash-only members stay undescribed to the model through their own frontmatter, which Claude honours.

### Readiness

- **Declared, never guessed** (ADR 0009): a **sidecar**, `agents/agent-harness.yaml` beside `SKILL.md` (the Codex `agents/openai.yaml` precedent; frontmatter keys would break claude.ai upload), else the **overlay** shipped in the contracts package, keyed by origin: repository identity and skill folder path. The sidecar wins whole. A member's origin is its source's identity and path, or what a provenance manifest names, so vendored copies of the Pocock set match the overlay for `mattpocock/skills`. An invalid sidecar is a warning on the member and counts as none.
- **Shape**: `version: 1` and a list of checks, each a kind with its parameters, an optional one-line `why` and an optional `fix` (a slash command or a Set up step id).
- **The seven kinds**, evaluated on the environment in the session's workspace (or the one named), paths relative to the repository root, else the workspace:
  - `file`: one of `paths` exists and holds each listed heading with content under it;
  - `tool`: a command on the PATH a run on this environment gets;
  - `secret`: a key-manager reference resolves through #91's registry, never by asking for the value in a session;
  - `git`: one of `repository`, `merge-in-progress`, `changes-since` (a ref, preset the merge base with the default branch) and `forge-account` (the repository's origin has a forge account here: the tracker check, chosen default, ADR 0012);
  - `skill`: a named member is in the account's set, enabled, and model-invocable unless the check says otherwise;
  - `mcp`: the tool-server factory gives the session's next run a server of that name (without a session, a new session of that account and workspace);
  - `provider`: the account's provider is among those listed, or its adapter declares the named capability.
- **Result**: `ready`; `setup-needed` with every failing check and the first one's `why` and `fix`; `unsupported` when a `provider` check fails. A skill declaring nothing is `ready`. Readiness is advisory in milestone 1: it never blocks an invocation or changes the set; the planning-mode strip that will consume it stays fog.
- `skills.readiness {sessionId | accountId and workspace, names?, refresh?}` (`read`): each check within five seconds and the call within ten, a check that runs out failing as "could not be checked in time"; results cached sixty seconds per workspace, account, session and fingerprint unless `refresh` (chosen defaults). The composer's `/` menu and the Skills pane show it.
- **The shipped overlay** covers the Pocock set (research, sections 8 and 9): `docs/agents/issue-tracker.md` for to-spec, to-tickets, triage, wayfinder and code-review, fixed by `/setup-matt-pocock-skills`; `docs/agents/triage-labels.md` for triage; an `Agent skills` heading in `CLAUDE.md` or `AGENTS.md`; `merge-in-progress` for resolving-merge-conflicts; `changes-since` for code-review; `package.json` for setup-pre-commit; `skill` checks for the callees each names; `forge-account` for the tracker-driven ones.

### Standing instructions and the composer

- **Order** (ADR 0009, ADR 0030's default, ADR 0011): the user layer (the orientation block while `instructions.orientation` is on, then the account's enabled owned instructions in list order), the team-bank layer (#90's renderer), the project layer, the session layer, a bot's persona (empty until the Bot object, #92 and milestone 2), then always-on skills (the account's, then the run's extra names). The run's own text follows the composed text (#138: a completions request's `systemPrompt`, system and developer messages).
- **The project layer is native for Claude**: under trust the `project` source loads the repository's instructions through Claude's own memory loading, beside the appended text rather than inside it, so the composer adds nothing. An adapter without native project instructions (the local loop, milestone 2) is given `AGENTS.md`, else `CLAUDE.md`, from the repository root under trust.
- **Headings** (chosen default): `# Standing instructions` over each owned instruction as `## <title>`; `# Instructions for this session`; `# Persona`; each always-on skill under `# Always-on skill: <name>` with its sentence (follow it for the whole session; its files are relative to its folder in the generation), the body cut at 60,000 characters, with a note at the cut that names the skill's file so the model can read the rest (chosen default). The orientation block's and the bank layer's headings are #91's and #90's.
- **Deterministic**: for unchanged state the text is byte-identical, since Claude fixes it at spawn and any other text costs a fresh process (#138). Every layer renders from state alone, never from a clock: a layer states a status and when it last changed, never "verified 3 min ago".
- **The seam grows**: the scope gains the trust key and decision, the run's origin, the bot (null in milestone 1), the run's extra always-on names and the account's instruction channel. The result is the text and a **manifest**: per layer its ids, versions and characters; always-on names with origins and commits; the skill set's fingerprint; the registries the orientation seam could not read (it now returns them beside its text); what was left out and why. A run of the queue takes the extra names of the run before it, held in memory as its own instructions are (#138).
- **Channel**: `none` receives nothing and the manifest says so. Under a character cap, always-on skills are left out last first, then owned instructions last first, and the manifest names them (chosen default; Claude's cap is null).
- **`run.instructions.composed`**: the host's, appended after `run.started`, not `list`: the manifest and the text's digest, never the text; compaction may fold it. `instructions.preview {sessionId | accountId and workspace}` (`read`) answers what a run would get now: each part with its layer and title, the text, the manifest.
- **Completions** (#138): `alwaysOnSkills` is honoured: each name enabled for the run's account joins the extra names, and any other is reported in `agent-harness.ignored` at its path. The rest of #138's join stands.

### Owned instructions

- **Record** (ADR 0030): id (client-minted), title (1 to 120 characters), body (Markdown, at most 20,000 characters), origin (catalogue id and version, or null), scope (`all`, which also reaches accounts added later, or account ids), enabled, position (a fractional key, session-state's ordering); the bounds and `all` are chosen defaults. On the `instructions` stream: `instructions.created`, `instructions.edited` (title and body), `instructions.scope-set`, `instructions.enabled-set`, `instructions.moved`, `instructions.version-resolved`, `instructions.removed`, `instructions.suggestion-dismissed`, `instructions.suggestion-restored`; one command per field, as for sessions (ADR 0003): `instructions.create`, `instructions.edit`, `instructions.setScope`, `instructions.setEnabled`, `instructions.move`, `instructions.resolveVersion`, `instructions.remove`, `instructions.dismissSuggestion`, `instructions.restoreSuggestion`.
- **Ticking** a suggestion is `instructions.create` with its catalogue id, copying the text and version; Custom is a title and body with no origin; the seeded "About my setup" is #88's `instructions.create` from the Setup entry.
- **A newer catalogue version** shows on `instructions.list` as `newerVersion`; `instructions.diff` answers the catalogue's old text against the new and the copy against the new; `instructions.resolveVersion {choice}` either replaces (body and version, the client saying edits are lost) or keeps (version raised, body kept, so the badge clears until the next version). Nothing updates silently, an unedited copy included.
- **Removal is remembered**: removing a copy with an origin dismisses its entry on this environment, listed under the Dismissed fold with Restore; switching off keeps the copy.
- **Minted** (ADR 0019): `instructions.import {sessionId, path, catalogueId?}` reads a Markdown file inside a minted session's scratch workspace (any other path is `invalid_params`) into a new owned instruction with that origin, its first heading the title.
- **The Orientation row** (ADR 0030): first on `instructions.list`, read-only: the `instructions.orientation` key (preset on, written by the Instructions step) and the rendered text through the preview, verification lines included; never edited or removed. Every row carries the environment's accounts, each with whether its adapter has an instruction channel, so a channel-less account shows dim with its reason.

### Session instructions

Chosen in the syncing's build (#499), for review:

- **When**: the start's pass syncs every unpinned source at once, past the startup gate once the wire is open. The six-hour timer is one 18-minute tick (six hours over the twenty sources the limit allows); each tick from six hours after start is one position's turn (`(position - 1) mod 20`), so each unpinned source syncs once every six hours, 18 minutes after the one added before it. The syncer (`skills/sync.ts`) is the only place that decides when.
- **One sync per source**: a Pull now, the timer or the start joins a sync of the source in flight that fetches the same branch; one of another branch (a source moved to another branch meanwhile) waits for it and then runs.
- **A sync is the environment's**: it appends `skills.source-synced` and `skills.updated` as `system:skill-sync`, checked as of its own transaction, so a source removed, or whose follow changed, while it fetched records nothing, and a sync the environment's close (a drain) cuts records nothing either: the close stops its git and settles once the sync has ended, so nothing it would clone or export under the data directory outlives the close (#1014). Pull now's receipt therefore appends nothing of its own (`changed: false`) and answers the source as the sync left it; a source removed while it synced is `not_found`. A pinned source is `conflict`, reason `pinned`, with the commit.
- **What counts as a change**: for `ok` the commit and the members; for `failed` the problem, not git's line, which can name timings; for `layout_moved` the commit fetched. A failure's line is git's when the outcome began. A fetch stopped at its sixty seconds says `git was stopped after 60 seconds.`, the probe's too.
- **The attempt's time** (`attemptedAt` on a listed source) is when a fetch of the source last ended: its add, a sync, or a pin at another commit. It raises no notice alone.
